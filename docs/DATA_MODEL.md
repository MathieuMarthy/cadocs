# Data model

The schema targets SQLite first and stays portable to PostgreSQL (ADR 0002). The SQL below runs on SQLite. Each divergence for PostgreSQL is listed in [Portability](#portability).

## Conventions

- **Ids** are UUIDv7 stored as `TEXT`. They are generated by the application, sort by creation time, and reveal nothing about row counts.
- **Timestamps** are `BIGINT` milliseconds since the Unix epoch, in UTC.
- **Booleans** are `SMALLINT` with a `CHECK (x IN (0, 1))`.
- **Enums** are `TEXT` with a `CHECK` constraint.
- **Binary data** is `BLOB` (`BYTEA` on PostgreSQL).
- **Deletion**: pages and spaces use a `deleted_at` soft delete (trash). A job purges them after `CADOCS_TRASH_DAYS`. Other rows are deleted for real.

## Accounts

```sql
CREATE TABLE users (
    id             TEXT PRIMARY KEY,
    email          TEXT NOT NULL,            -- stored lowercased
    name           TEXT NOT NULL,
    password_hash  TEXT,                     -- NULL for OIDC-only accounts
    is_instance_admin SMALLINT NOT NULL DEFAULT 0 CHECK (is_instance_admin IN (0, 1)),
    disabled_at    BIGINT,
    created_at     BIGINT NOT NULL,
    updated_at     BIGINT NOT NULL,
    UNIQUE (email)
);

CREATE TABLE user_identities (               -- OIDC, V1
    provider   TEXT NOT NULL,
    subject    TEXT NOT NULL,
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at BIGINT NOT NULL,
    PRIMARY KEY (provider, subject)
);
CREATE INDEX user_identities_user ON user_identities(user_id);

CREATE TABLE sessions (
    token_hash TEXT PRIMARY KEY,             -- SHA-256 of the cookie value
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at BIGINT NOT NULL,
    last_seen_at BIGINT NOT NULL,
    expires_at BIGINT NOT NULL
);
CREATE INDEX sessions_user ON sessions(user_id);
CREATE INDEX sessions_expiry ON sessions(expires_at);

CREATE TABLE password_resets (               -- ADR 0013
    token_hash TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_by TEXT REFERENCES users(id) ON DELETE SET NULL, -- NULL: from the CLI
    expires_at BIGINT NOT NULL,
    created_at BIGINT NOT NULL
);
CREATE INDEX password_resets_user ON password_resets(user_id);
```

`sessions.last_seen_at` is written at most once every 5 minutes, so that reads do not turn into writes. Each such write also extends `expires_at`.

## Workspaces, groups and spaces

```sql
CREATE TABLE workspaces (
    id         TEXT PRIMARY KEY,
    slug       TEXT NOT NULL UNIQUE,
    name       TEXT NOT NULL,
    language   TEXT NOT NULL DEFAULT 'en',   -- search stemming (ADR 0007)
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL
);

CREATE TABLE workspace_members (
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role         TEXT NOT NULL CHECK (role IN ('owner', 'admin', 'member')),
    created_at   BIGINT NOT NULL,
    PRIMARY KEY (workspace_id, user_id)
);
CREATE INDEX workspace_members_user ON workspace_members(user_id);

CREATE TABLE workspace_invitations (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    email        TEXT NOT NULL,
    role         TEXT NOT NULL CHECK (role IN ('admin', 'member')),
    token_hash   TEXT NOT NULL UNIQUE,
    invited_by   TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    expires_at   BIGINT NOT NULL,
    created_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, email)             -- a new link replaces the last
);

CREATE TABLE groups (                        -- V1
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,
    created_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, name)
);

CREATE TABLE group_members (
    group_id TEXT NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    user_id  TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    PRIMARY KEY (group_id, user_id)
);
CREATE INDEX group_members_user ON group_members(user_id);

CREATE TABLE spaces (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    slug         TEXT NOT NULL,
    name         TEXT NOT NULL,
    description  TEXT NOT NULL DEFAULT '',
    default_role TEXT CHECK (default_role IN ('editor', 'commenter', 'viewer')), -- NULL: invited members only
    deleted_at   BIGINT,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, slug)
);

-- A grant targets a user or a group, never both.
CREATE TABLE space_grants (
    id       TEXT PRIMARY KEY,
    space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    user_id  TEXT REFERENCES users(id) ON DELETE CASCADE,
    group_id TEXT REFERENCES groups(id) ON DELETE CASCADE,
    role     TEXT NOT NULL CHECK (role IN ('admin', 'editor', 'commenter', 'viewer')),
    created_at BIGINT NOT NULL,
    CHECK ((user_id IS NULL) <> (group_id IS NULL)),
    UNIQUE (space_id, user_id),
    UNIQUE (space_id, group_id)
);
CREATE INDEX space_grants_user ON space_grants(user_id);
CREATE INDEX space_grants_group ON space_grants(group_id);
```

`UNIQUE` treats `NULL` values as distinct on both engines, which is what these two constraints need.

A member who leaves or is removed loses their grants and group memberships in that workspace, so an invitation later starts from nothing. A grant only targets a member or a group of the workspace of the space.

## Pages

The tree lives in SQL. `position` is a fractional index (a string that sorts between its neighbours), so reordering never rewrites siblings. The server computes it (`cadocs_core::position`), and `pages_sibling_keys` keeps a key unique among the children of a parent, trashed ones included: they keep theirs, so a restore has its place waiting. A tree has at most 100 levels: SQLite stops nested triggers at 1000, so a deeper chain could never be deleted, nor could its workspace.

```sql
CREATE TABLE pages (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    space_id     TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    parent_id    TEXT REFERENCES pages(id) ON DELETE CASCADE,
    position     TEXT NOT NULL,
    slug         TEXT NOT NULL,              -- short random id for URLs
    title        TEXT NOT NULL DEFAULT '',   -- copy of the Yjs title
    created_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    updated_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    deleted_at   BIGINT,
    deleted_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, slug)
);
CREATE INDEX pages_tree ON pages(space_id, parent_id, position);
CREATE INDEX pages_parent ON pages(parent_id);
CREATE INDEX pages_recent ON pages(workspace_id, updated_at);
CREATE UNIQUE INDEX pages_sibling_keys ON pages(coalesce(parent_id, space_id), position);
CREATE INDEX pages_trash ON pages(space_id, deleted_at) WHERE deleted_at IS NOT NULL;

-- V2. Restrictions narrow access and never widen it (ADR 0009).
CREATE TABLE page_restrictions (
    page_id  TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    user_id  TEXT REFERENCES users(id) ON DELETE CASCADE,
    group_id TEXT REFERENCES groups(id) ON DELETE CASCADE,
    access   TEXT NOT NULL CHECK (access IN ('read', 'edit')),
    CHECK ((user_id IS NULL) <> (group_id IS NULL)),
    UNIQUE (page_id, user_id),
    UNIQUE (page_id, group_id)
);
CREATE INDEX page_restrictions_user ON page_restrictions(user_id);
CREATE INDEX page_restrictions_group ON page_restrictions(group_id);

CREATE TABLE page_shares (
    id                 TEXT PRIMARY KEY,
    page_id            TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    token              TEXT NOT NULL UNIQUE,  -- 128 random bits, in the public URL
    include_children   SMALLINT NOT NULL DEFAULT 0 CHECK (include_children IN (0, 1)),
    indexable          SMALLINT NOT NULL DEFAULT 0 CHECK (indexable IN (0, 1)), -- allow search engines
    created_by         TEXT REFERENCES users(id) ON DELETE SET NULL,
    expires_at         BIGINT,
    created_at         BIGINT NOT NULL
);
CREATE INDEX page_shares_page ON page_shares(page_id);
```

**Moving.** A move within a space changes one row. A move to another space also rewrites `space_id` on every descendant, trashed ones included, in the same transaction. The server refuses to move a page under itself or under one of its descendants, using a recursive query on `parent_id`. A move across workspaces is refused.

**Trash.** Trashing a page sets the same `deleted_at` on the page and on every descendant that is not already trashed, in one transaction, so `deleted_at IS NULL` is enough to filter any read. Restoring brings back the rows with that exact `deleted_at` in the subtree, so a page trashed separately earlier stays in the trash. A trash date is later than any date already in the subtree, so two trashes in one millisecond stay apart. If the parent of the restored page is still trashed, the page goes last at the root of its space.

**Purge.** Deleting a trashed page cascades to all that is under it, including pages trashed separately before it: they have no parent left to return to.

A trashed space keeps its pages as they are, and access rules treat the whole space as absent ([PERMISSIONS.md](PERMISSIONS.md)).

## Document content

`doc_updates` is an append-only log and `doc_snapshots` holds the compacted state. To load a page: read its snapshot, then apply every update with `seq` greater than `snapshot.upto_seq`.

A Yjs document has two root types: `title`, a `Y.Text`, and `default`, the `XmlFragment` that TipTap edits. Each flush copies `title` to `pages.title`, at most 500 characters of it, and sets `updated_at` and `updated_by` to the last writer, in the transaction of its updates. A writer whose account is gone leaves `updated_by` as it was. Writing every time instead of on a change means a copy that ran ahead of the log before a crash gets corrected.

```sql
CREATE TABLE doc_snapshots (
    page_id    TEXT PRIMARY KEY REFERENCES pages(id) ON DELETE CASCADE,
    state      BLOB NOT NULL,                -- Yjs update v1, full document
    upto_seq   BIGINT NOT NULL,              -- last doc_updates.seq included
    updated_at BIGINT NOT NULL
);

CREATE TABLE doc_updates (
    page_id    TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    seq        BIGINT NOT NULL,              -- per page, assigned by the room
    data       BLOB NOT NULL,                -- Yjs update v1
    created_at BIGINT NOT NULL,
    PRIMARY KEY (page_id, seq)
);

CREATE TABLE page_revisions (
    id         TEXT PRIMARY KEY,
    page_id    TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    number     BIGINT NOT NULL,
    title      TEXT NOT NULL,
    state      BLOB NOT NULL,                -- zstd-compressed Yjs state at that moment
    authors    TEXT NOT NULL,                -- JSON array of user ids since the last revision
    created_at BIGINT NOT NULL,
    UNIQUE (page_id, number)
);
```

The `seq` keeps growing after compaction, because `upto_seq` records the position. This lets a compaction run while updates arrive: the transaction deletes only rows with `seq <= upto_seq`.

A revision is created by a job after `CADOCS_REVISION_PAUSE_SECS` without edits, or after `CADOCS_REVISION_MAX_SECS` of continuous activity, and only if the content changed. A revision holds a full state rather than a Yjs snapshot. It can then be rendered or restored without the document's complete history, and old revisions can be pruned. All revisions are kept for `CADOCS_REVISION_KEEP_DAYS`. Older ones are thinned to one per day, and the most recent revision is never pruned.

Restoring cannot simply merge the old state, because a CRDT merge would keep current content. In one room transaction, the server renders the revision into the AST (ADR 0008), clears `default` and `title`, and writes the AST back. Connected clients receive this as a normal edit, and the previous content stays available as a revision of its own, created first.

## Comments and mentions

```sql
CREATE TABLE comments (
    id           TEXT PRIMARY KEY,
    page_id      TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    parent_id    TEXT REFERENCES comments(id) ON DELETE CASCADE, -- one level of replies
    author_id    TEXT REFERENCES users(id) ON DELETE SET NULL,
    body         TEXT NOT NULL,              -- Markdown
    anchor_start BLOB,                       -- Yjs RelativePosition, NULL: reply or whole page
    anchor_end   BLOB,
    anchor_text  TEXT,                       -- quoted text, shown if the anchor is lost
    resolved_at  BIGINT,
    resolved_by  TEXT REFERENCES users(id) ON DELETE SET NULL,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL
);
CREATE INDEX comments_page ON comments(page_id, created_at);
CREATE INDEX comments_parent ON comments(parent_id);

CREATE TABLE mentions (
    id          TEXT PRIMARY KEY,
    user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,  -- who is mentioned
    page_id     TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    comment_id  TEXT REFERENCES comments(id) ON DELETE CASCADE,        -- NULL: in the page body
    author_id   TEXT REFERENCES users(id) ON DELETE SET NULL,
    read_at     BIGINT,
    created_at  BIGINT NOT NULL
);
CREATE INDEX mentions_user ON mentions(user_id, read_at);
CREATE INDEX mentions_page ON mentions(page_id);
CREATE INDEX mentions_comment ON mentions(comment_id);
```

A comment's anchor is a pair of Yjs relative positions stored here, so it follows edits and merges without writing to the document. A `commenter` stays read-only on the wire (ADR 0012). Mentions in the page body are diffed from the Yjs content by the indexing job.

## Attachments

```sql
CREATE TABLE attachments (
    id           TEXT PRIMARY KEY,           -- also the storage key
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    file_name    TEXT NOT NULL,              -- display only, never a path
    content_type TEXT NOT NULL,
    size         BIGINT NOT NULL,
    sha256       TEXT NOT NULL,
    uploaded_by  TEXT REFERENCES users(id) ON DELETE SET NULL,
    created_at   BIGINT NOT NULL
);
CREATE INDEX attachments_workspace ON attachments(workspace_id);
CREATE INDEX attachments_uploaded_by ON attachments(uploaded_by);  -- deleting a user

CREATE TABLE attachment_refs (
    attachment_id TEXT NOT NULL REFERENCES attachments(id) ON DELETE CASCADE,
    page_id       TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    PRIMARY KEY (attachment_id, page_id)
);
CREATE INDEX attachment_refs_page ON attachment_refs(page_id);
```

An upload creates the first reference. The indexing job adds one for each attachment it finds in a page's content, so an image pasted into another page is readable there, after a short delay.

Editing never removes a reference, because a revision may still show the file. References disappear when a page is purged or through `DELETE /attachments/{id}`. An attachment with no reference left is an orphan, and a job deletes it with its file. The cost is disk space: an image removed from a page stays stored until the page is purged or someone deletes the file. A revision restored after an explicit delete shows a placeholder.

The `purge_orphan_files` job runs at start and every hour. It deletes each orphan's row, then its file, then any file with no row that is over an hour old: a crash between an upload's rename and its record, a deleted workspace, a failed delete, or a backup's files newer than its database leave such files. A younger one may be an upload about to record its row. The quota sums `size` over the workspace's rows, so a file with no row counts against nothing.

A download needs read access to at least one referencing page. A public share serves a file only if a page covered by the share references it.

## Jobs

```sql
CREATE TABLE jobs (
    id          TEXT PRIMARY KEY,
    kind        TEXT NOT NULL,
    dedup_key   TEXT,                        -- e.g. 'reindex:<page id>'
    payload     TEXT NOT NULL DEFAULT '{}',  -- JSON
    status      TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'running', 'failed')),
    attempts    INTEGER NOT NULL DEFAULT 0,
    run_at      BIGINT NOT NULL,
    locked_at   BIGINT,
    last_error  TEXT,
    created_at  BIGINT NOT NULL
);
CREATE INDEX jobs_due ON jobs(status, run_at);
CREATE UNIQUE INDEX jobs_dedup ON jobs(dedup_key) WHERE dedup_key IS NOT NULL AND status = 'pending';
```

A finished job is deleted. A job that exhausts its attempts stays as `failed` for 30 days, for inspection. At startup, `running` jobs are reset to `pending`, because only one process exists (ADR 0006), and those out of attempts become `failed`. `jobs_dedup` only covers `pending`, so a change during a run queues another run. A retry or a reset that finds a pending job with its key gives way to it.

## Search

```sql
-- SQLite only. PostgreSQL uses a tsvector column instead, behind the same trait.
CREATE TABLE page_text (
    id         INTEGER PRIMARY KEY,          -- also the page_fts rowid
    page_id    TEXT NOT NULL UNIQUE REFERENCES pages(id) ON DELETE CASCADE,
    plain_text TEXT NOT NULL,                -- original words, for excerpts
    indexed_at BIGINT NOT NULL
);

CREATE VIRTUAL TABLE page_fts USING fts5(
    title,                                   -- stemmed (ADR 0007)
    body,                                    -- stemmed
    tokenize = "unicode61 remove_diacritics 2",
    prefix = '2 3'
);

CREATE TRIGGER page_text_delete AFTER DELETE ON page_text BEGIN
    DELETE FROM page_fts WHERE rowid = old.id;
END;
```

`page_fts` is linked by `rowid`, because a lookup on an `UNINDEXED` column would scan the whole table on every reindex. The trigger also runs on the cascade from `pages`.

Query shape, with permission filtering inside the SQL:

```sql
SELECT t.page_id, bm25(page_fts, 5.0, 1.0) AS score -- weights: title, body
FROM page_fts f
JOIN page_text t ON t.id = f.rowid
JOIN pages p ON p.id = t.page_id
WHERE page_fts MATCH ?1
  AND p.workspace_id = ?2
  AND p.deleted_at IS NULL
  AND p.space_id IN (/* readable spaces, trashed ones excluded */)
ORDER BY score
LIMIT 20;
```

## Portability

| Topic | SQLite | PostgreSQL |
| --- | --- | --- |
| Binary | `BLOB` | `BYTEA` |
| Search | FTS5 virtual table | `tsvector` column with a GIN index |
| Filtered unique index | Supported | Supported |
| `CHECK ((a IS NULL) <> (b IS NULL))` | Supported | Supported |
| Placeholders | `?1` | `$1`, handled by each store implementation |
| JSON columns | `TEXT` | `TEXT` at first, `JSONB` is possible later |
| Foreign keys | `PRAGMA foreign_keys = ON` on every connection | Always on |
| Claiming a job | Single writer, conditional `UPDATE` | `FOR UPDATE SKIP LOCKED` |

Migrations are kept in one folder per engine, so each can use its own syntax. Their results must match this document.
