# Data model

The schema targets SQLite first and stays portable to PostgreSQL (ADR 0002). The SQL below runs on SQLite. Each divergence for PostgreSQL is listed in [Portability](#portability).

## Conventions

- **Ids** are UUIDv7 stored as `TEXT`. They are generated by the application, sort by creation time, and reveal nothing about row counts.
- **Timestamps** are `BIGINT` milliseconds since the Unix epoch, in UTC.
- **Booleans** are `SMALLINT` with a `CHECK (x IN (0, 1))`.
- **Enums** are `TEXT` with a `CHECK` constraint.
- **Binary data** is `BLOB` (`BYTEA` on PostgreSQL).
- **Deletion**: pages and spaces use a `deleted_at` soft delete (trash). A job purges them later. Other rows are deleted for real.

## Accounts

```sql
CREATE TABLE users (
    id             TEXT PRIMARY KEY,
    email          TEXT NOT NULL,            -- stored lowercased
    name           TEXT NOT NULL,
    password_hash  TEXT,                     -- NULL for OIDC-only accounts
    is_instance_admin SMALLINT NOT NULL DEFAULT 0 CHECK (is_instance_admin IN (0, 1)),
    disabled_at    BIGINT,
    created_at     BIGINT NOT NULL,
    updated_at     BIGINT NOT NULL,
    UNIQUE (email)
);

CREATE TABLE user_identities (               -- OIDC, V1
    provider   TEXT NOT NULL,
    subject    TEXT NOT NULL,
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at BIGINT NOT NULL,
    PRIMARY KEY (provider, subject)
);
CREATE INDEX user_identities_user ON user_identities(user_id);

CREATE TABLE sessions (
    token_hash TEXT PRIMARY KEY,             -- SHA-256 of the cookie value
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at BIGINT NOT NULL,
    last_seen_at BIGINT NOT NULL,
    expires_at BIGINT NOT NULL
);
CREATE INDEX sessions_user ON sessions(user_id);
CREATE INDEX sessions_expiry ON sessions(expires_at);
```

## Workspaces, groups and spaces

```sql
CREATE TABLE workspaces (
    id         TEXT PRIMARY KEY,
    slug       TEXT NOT NULL UNIQUE,
    name       TEXT NOT NULL,
    language   TEXT NOT NULL DEFAULT 'en',   -- search stemming (ADR 0007)
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL
);

CREATE TABLE workspace_members (
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role         TEXT NOT NULL CHECK (role IN ('owner', 'admin', 'member')),
    created_at   BIGINT NOT NULL,
    PRIMARY KEY (workspace_id, user_id)
);
CREATE INDEX workspace_members_user ON workspace_members(user_id);

CREATE TABLE workspace_invitations (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    email        TEXT NOT NULL,
    role         TEXT NOT NULL CHECK (role IN ('admin', 'member')),
    token_hash   TEXT NOT NULL UNIQUE,
    invited_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    expires_at   BIGINT NOT NULL,
    created_at   BIGINT NOT NULL
);
CREATE INDEX workspace_invitations_workspace ON workspace_invitations(workspace_id);

CREATE TABLE groups (                        -- V1
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,
    created_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, name)
);

CREATE TABLE group_members (
    group_id TEXT NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    user_id  TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    PRIMARY KEY (group_id, user_id)
);
CREATE INDEX group_members_user ON group_members(user_id);

CREATE TABLE spaces (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    slug         TEXT NOT NULL,
    name         TEXT NOT NULL,
    description  TEXT NOT NULL DEFAULT '',
    default_role TEXT CHECK (default_role IN ('editor', 'commenter', 'viewer')), -- NULL: invited members only
    deleted_at   BIGINT,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, slug)
);

-- A grant targets a user or a group, never both.
CREATE TABLE space_grants (
    id       TEXT PRIMARY KEY,
    space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    user_id  TEXT REFERENCES users(id) ON DELETE CASCADE,
    group_id TEXT REFERENCES groups(id) ON DELETE CASCADE,
    role     TEXT NOT NULL CHECK (role IN ('admin', 'editor', 'commenter', 'viewer')),
    created_at BIGINT NOT NULL,
    CHECK ((user_id IS NULL) <> (group_id IS NULL)),
    UNIQUE (space_id, user_id),
    UNIQUE (space_id, group_id)
);
CREATE INDEX space_grants_user ON space_grants(user_id);
CREATE INDEX space_grants_group ON space_grants(group_id);
```

`UNIQUE` treats `NULL` values as distinct on both engines, which is what these two constraints need.

## Pages

The tree lives in SQL. Moving a page changes one row. `position` is a fractional index (a string that sorts between its neighbours), so reordering never rewrites siblings.

```sql
CREATE TABLE pages (
    id           TEXT PRIMARY KEY,
    workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    space_id     TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
    parent_id    TEXT REFERENCES pages(id) ON DELETE CASCADE,
    position     TEXT NOT NULL,
    slug         TEXT NOT NULL,              -- short random id for URLs
    title        TEXT NOT NULL DEFAULT '',
    icon         TEXT,
    created_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    updated_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
    deleted_at   BIGINT,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL,
    UNIQUE (workspace_id, slug)
);
CREATE INDEX pages_tree ON pages(space_id, parent_id, position);
CREATE INDEX pages_parent ON pages(parent_id);

-- V2. Restrictions narrow access and never widen it (ADR 0009).
CREATE TABLE page_restrictions (
    page_id  TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    user_id  TEXT REFERENCES users(id) ON DELETE CASCADE,
    group_id TEXT REFERENCES groups(id) ON DELETE CASCADE,
    access   TEXT NOT NULL CHECK (access IN ('read', 'edit')),
    CHECK ((user_id IS NULL) <> (group_id IS NULL)),
    UNIQUE (page_id, user_id),
    UNIQUE (page_id, group_id)
);
CREATE INDEX page_restrictions_user ON page_restrictions(user_id);
CREATE INDEX page_restrictions_group ON page_restrictions(group_id);

CREATE TABLE page_shares (
    id                 TEXT PRIMARY KEY,
    page_id            TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    token              TEXT NOT NULL UNIQUE,  -- 128 random bits, in the public URL
    include_children   SMALLINT NOT NULL DEFAULT 0 CHECK (include_children IN (0, 1)),
    created_by         TEXT REFERENCES users(id) ON DELETE SET NULL,
    expires_at         BIGINT,
    created_at         BIGINT NOT NULL
);
CREATE INDEX page_shares_page ON page_shares(page_id);
```

## Document content

`doc_updates` is an append-only log and `doc_snapshots` holds the compacted state. To load a page: read its snapshot, then apply every update with `seq` greater than `snapshot.upto_seq`.

```sql
CREATE TABLE doc_snapshots (
    page_id    TEXT PRIMARY KEY REFERENCES pages(id) ON DELETE CASCADE,
    state      BLOB NOT NULL,                -- Yjs update v1, full document
    upto_seq   BIGINT NOT NULL,              -- last doc_updates.seq included
    updated_at BIGINT NOT NULL
);

CREATE TABLE doc_updates (
    page_id    TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    seq        BIGINT NOT NULL,              -- per page, assigned by the room
    data       BLOB NOT NULL,                -- Yjs update v1
    created_at BIGINT NOT NULL,
    PRIMARY KEY (page_id, seq)
);

CREATE TABLE page_revisions (
    id         TEXT PRIMARY KEY,
    page_id    TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    number     BIGINT NOT NULL,
    title      TEXT NOT NULL,
    state      BLOB NOT NULL,                -- zstd-compressed Yjs state at that moment
    authors    TEXT NOT NULL,                -- JSON array of user ids since the last revision
    created_at BIGINT NOT NULL,
    UNIQUE (page_id, number)
);
```

The `seq` keeps growing after compaction, because `upto_seq` records the position. This lets a compaction run while updates arrive: the transaction deletes only rows with `seq <= upto_seq`.

A revision is created by a job, after a pause in editing or at most every N minutes of activity, and only if the content changed. A revision holds a full state rather than a Yjs snapshot. It can then be rendered or restored without the document's complete history, and old revisions can be pruned. Restoring a revision applies a new update on top of the current document, so it reaches connected clients as a normal edit.

## Comments and mentions

```sql
CREATE TABLE comments (
    id           TEXT PRIMARY KEY,
    page_id      TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    parent_id    TEXT REFERENCES comments(id) ON DELETE CASCADE, -- one level of replies
    author_id    TEXT REFERENCES users(id) ON DELETE SET NULL,
    body         TEXT NOT NULL,              -- Markdown
    resolved_at  BIGINT,
    resolved_by  TEXT REFERENCES users(id) ON DELETE SET NULL,
    created_at   BIGINT NOT NULL,
    updated_at   BIGINT NOT NULL
);
CREATE INDEX comments_page ON comments(page_id, created_at);
CREATE INDEX comments_parent ON comments(parent_id);

CREATE TABLE mentions (
    id          TEXT PRIMARY KEY,
    user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,  -- who is mentioned
    page_id     TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    comment_id  TEXT REFERENCES comments(id) ON DELETE CASCADE,        -- NULL: in the page body
    author_id   TEXT REFERENCES users(id) ON DELETE SET NULL,
    read_at     BIGINT,
    created_at  BIGINT NOT NULL
);
CREATE INDEX mentions_user ON mentions(user_id, read_at);
CREATE INDEX mentions_page ON mentions(page_id);
CREATE INDEX mentions_comment ON mentions(comment_id);
```

A comment is anchored in the document, not in SQL: the editor stores a mark with the comment id around the commented range, so the anchor follows edits and merges for free. Mentions in the page body are diffed from the Yjs content by the indexing job.

## Jobs

```sql
CREATE TABLE jobs (
    id          TEXT PRIMARY KEY,
    kind        TEXT NOT NULL,
    dedup_key   TEXT,                        -- e.g. 'reindex:<page id>'
    payload     TEXT NOT NULL DEFAULT '{}',  -- JSON
    status      TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'running', 'failed')),
    attempts    INTEGER NOT NULL DEFAULT 0,
    run_at      BIGINT NOT NULL,
    locked_at   BIGINT,
    last_error  TEXT,
    created_at  BIGINT NOT NULL
);
CREATE INDEX jobs_due ON jobs(status, run_at);
CREATE UNIQUE INDEX jobs_dedup ON jobs(dedup_key) WHERE dedup_key IS NOT NULL AND status = 'pending';
```

A finished job is deleted. A job that exhausts its attempts stays as `failed`, for inspection. At startup, `running` jobs are reset to `pending`, because only one process exists (ADR 0006).

## Search

```sql
-- SQLite only. PostgreSQL uses a tsvector column instead, behind the same trait.
CREATE TABLE page_text (
    page_id    TEXT PRIMARY KEY REFERENCES pages(id) ON DELETE CASCADE,
    plain_text TEXT NOT NULL,                -- original words, for excerpts
    indexed_at BIGINT NOT NULL
);

CREATE VIRTUAL TABLE page_fts USING fts5(
    page_id UNINDEXED,
    title,                                   -- stemmed (ADR 0007)
    body,                                    -- stemmed
    tokenize = "unicode61 remove_diacritics 2",
    prefix = '2 3'
);
```

Query shape, with permission filtering inside the SQL:

```sql
SELECT f.page_id, bm25(page_fts, 5.0, 1.0) AS score
FROM page_fts f
JOIN pages p ON p.id = f.page_id
WHERE page_fts MATCH ?1
  AND p.workspace_id = ?2
  AND p.deleted_at IS NULL
  AND p.space_id IN (/* spaces readable by the user */)
ORDER BY score
LIMIT 20;
```

## Portability

| Topic | SQLite | PostgreSQL |
| --- | --- | --- |
| Binary | `BLOB` | `BYTEA` |
| Search | FTS5 virtual table | `tsvector` column with a GIN index |
| Filtered unique index | Supported | Supported |
| `CHECK ((a IS NULL) <> (b IS NULL))` | Supported | Supported |
| Placeholders | `?1` | `$1`, handled by each store implementation |
| JSON columns | `TEXT` | `TEXT` at first, `JSONB` is possible later |
| Foreign keys | `PRAGMA foreign_keys = ON` on every connection | Always on |
| Claiming a job | Single writer, conditional `UPDATE` | `FOR UPDATE SKIP LOCKED` |

Migrations are kept in one folder per engine, so each can use its own syntax. Their results must match this document.

## Prototype subset

The prototype only creates `doc_updates` and `doc_snapshots`, with `doc_id` in place of `page_id` and no foreign key, because the `pages` table does not exist yet.
