# Content

What a change to `cadocs-content`, or to the editor's blocks, must know.

- **One schema, checked both ways:** `schema.rs` holds the nodes and marks, `src/editor/registry.ts` the editor's. `npm --prefix web run schema` writes `tests/tiptap-schema.json` and `tests/every-node.bin`, the Yjs update `@tiptap/y-tiptap` writes for `tests/every-node.json`, and `npm --prefix web run build` fails while either is stale. `tests/schema.rs` compares the schemas, `tests/editor.rs` reads the update as `every_node()` (`tests/common/mod.rs`) and checks that `yjs::write` builds the same tree, attribute for attribute. A new block therefore means: the extension in the registry, its spec in `schema.rs`, a variant in `ast.rs`, a case in each module, and the node in `every_node()` and `every-node.json`. `the_sample_uses_every_node_and_mark_of_the_schema` fails until the sample has it.
- **Layout:** the binding writes every non-null node attribute, defaults included, and a mark's value is its attribute object (`bold: {}`, `link: { href, target, rel, class, title }` with its nulls). Numbers come back as `Number::Int` or `Number::Float`, so read them through `int`. Text runs go in with explicit attributes, even empty ones, since a Yjs insert without them takes the marks of the text before it.
- **Reading:** a child where the schema expects another node (a paragraph right in a list or a row) keeps its blocks, wrapped in an item, row or cell. An unknown element keeps its blocks if it holds elements, else its text as a paragraph, inline its text, and an unknown mark is dropped, each with a `warn!`. `plugin.data` is any JSON in Yjs, kept as JSON text in the AST and parsed back on write. The reader takes a `ReadTxn`, so it runs inside `DocRegistry::read` (see [collab notes](collab.md)), and `yjs::write` replaces the whole fragment in one transaction, as a revision restore needs.
- **Writing fixes content up:** an empty `+` container gets an empty paragraph, a list item starts with one, a summary holds text only, a heading from Markdown is at most level 3 (the editor shows 1 to 3).
- **HTML:** every text and attribute goes through `escape`, links through `url::allowed` (http, https, mailto, tel, or no scheme; control characters refused anywhere). Values used as keywords (code language, callout kind, list type, cell alignment) are checked against a character set or a list, and dropped otherwise. No `style` attribute is written, for the CSP: cell alignment is `data-align`, list depth in the table of contents `data-depth`. A stored link `class`, `target` or `rel` is never rendered, and every link gets `rel="noopener noreferrer nofollow"`. Headings get `id="h-<number>"`, the number the editor shows, which the table of contents links to. Classes for the public stylesheet: `tasks`, `task`, `callout` (with `data-kind`), `toc`, `toc-number`, `page-link`, `page-link-missing`, `plugin`.
- **Page titles:** renderers take a `PageTitles` (any `Fn(&str) -> Option<String>`), which the caller answers with the reader's permissions. `None` shows `page not found`. Plain text leaves page links out, so search never finds a page by the title of another.
- **Markdown conventions:** listed at the top of `markdown.rs`, with what is lost. A list right after a list of its family takes the other marker (`*`, `)`), or Markdown would merge them. `[TOC]` is told from an escaped `\[TOC\]` by its source range, since both parse to the same text. Raw HTML imports as text, except the four toggle tags on their own lines, `<br>` alone (an empty paragraph), and the inline tags the writer uses (`<u>`, `<strong>`, `<em>`, `<s>`, `<br>`). `&` is escaped in link addresses and titles, so an exported `javascript&#58;` never becomes a script link in another renderer. Whether a `*` delimiter would be read is approximated by `flanks`, which errs towards the HTML tag. An image or a plain link to `ATTACHMENT_PATH` alone in a paragraph imports as an `image` or `file` block. Any other image, or one beside text, imports as its alternative text, and a link to an attachment beside text stays a link.
- **Left open:** a paragraph holding only a hard break exports as `<br>`, which reads back as an empty paragraph. The schema check compares content, groups and attribute defaults, not each node's allowed marks: the writer keeps marks in `detailsSummary`, whose `text*` may refuse them, unverified. A page id is written as is after `/?page=`, which assumes server ids (no spaces or brackets). Step 18 brings the crate into the binary, through the indexing job: `read_page` reads the title and content in one transaction, `to_text` makes the indexed text, and `Document::attachments` the ids it references.
- **Attachments:** `image { id, alt }` and `file { id, name }` are atom blocks holding an attachment id, never bytes or a URL. Renderers build the address from `ATTACHMENT_PATH` (`/api/v1/attachments/`), so a public share (V1) needs its own path there, as it does for page links. The text renderer gives the alternative text and the file name, so search finds both.
- **Addresses (step 20):** `Links` in `lib.rs` says where Markdown points attachments and pages, and reads them back; `to_markdown` and `from_markdown` use `Relative`, the server's own paths, and `_with` takes another. The server's export and import (`api/markdown.rs`) use absolute addresses, and zip entries for attachments, whose ids `Document::map_attachments` replaces once stored. The HTML renderer still writes `ATTACHMENT_PATH` and `PAGE_PATH` alone: a public share (V1) or an HTML export needs the same parameter there.
