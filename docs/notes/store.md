# Store and permissions

What a change to the stores, roles or the workspace, space and page routes must know.

- **Store:** `DocStore` (`cadocs-store`) uses native `impl Future + Send` methods, so collab is generic over it instead of using `dyn`. The room assigns `seq`, starting from `StoredDoc::last_seq() + 1`. `compact` refuses a snapshot older than the stored one with `StoreError::StaleSnapshot`. `append_updates` can be replayed after a lost commit, and returns `StoreError::SeqConflict` for a `seq` the snapshot covers or that holds other data. A room must flush its queue before it compacts. `SqliteStore::open` takes the database file path, and its parent folder must exist. There is no in-memory store or `close()` yet. `StoreError` wraps `sqlx::Error`, so a failure-injecting test store can return `sqlx::Error::PoolTimedOut`. A document needs its row in `pages`, so a test on `SqliteStore` inserts one, and `append_updates` and `compact` answer `PageNotFound` without it. `append_updates` also takes a `DocEdit`, the title and author for that row, whatever the batch.
- **SQLite upkeep (ADR 0019):** new databases use `auto_vacuum = INCREMENTAL`, and `open` converts an older one with a `VACUUM`. `JobStore::maintain_database` runs `incremental_vacuum` by steps of 1,024 pages, stopping when a step frees nothing, then `optimize`. A flush that frees pages between two steps can end a run early, and the next hour finishes it. Its job, `MAINTAIN_DATABASE`, is the last of `Cleanup::RECURRING`, so it frees what the purges emptied. Do not add `mmap_size` or a forced `wal_checkpoint(TRUNCATE)`. Step 21's `backup` needs no checkpoint: `VACUUM INTO` reads the WAL. A PostgreSQL store implements `maintain_database` as nothing.
- **SQLite advisory:** RUSTSEC-2026-0459 (SQLite before 3.54.0, a crafted `-wal` beside the database) is ignored in `deny.toml`: sqlx 0.9.0 caps `libsqlite3-sys` below 0.38, and the fix is in 0.39. Take the sqlx release that lifts the cap, then remove the ignore.
- **Snapshots (step 20c):** `compact` writes the state with zstd level 3 and `codec = 1`, and `load` decodes by `codec`, so rows from before stay readable and shrink at their next compaction. A state that does not decompress is `StoreError::CorruptSnapshot`. The ratio on seeded pages is 3.3 (step 20c, [benchmark notes](benchmark.md)); step 23 did not measure it again.
- **Store load:** `load` holds a document's whole update log in memory. Measured at 3.0 MB more for 100 documents of 2,000 rows, so it stays.
- **Permissions:** `cadocs-core::permissions` covers the matrix, the special cases and the recompute of page sockets. `would_remove_last_instance_admin` is a separate check, called by `delete_user` and `administer_user` in the store. `Authorizer` and `PageAuthorizer`, which resolves the role through `PageStore` and the session through `AccountStore`, are in `cadocs-collab`. **A handler whose change can alter what a user reaches calls `state.access_changed()` once it is stored**: that wakes `watch_access` in `lib.rs`, which runs `DocRegistry::recheck` over every page and events socket. It does not wait, so a test waits for the close frame. The timer of `CADOCS_SOCKET_RECHECK_SECS` covers expired sessions, commands beside the server and a failed pass. `upgrade` rechecks once after joining, which closes the race with a change landing before the join. A pass costs two queries per socket with no dedupe, and step 23 should measure it at `CADOCS_MAX_SOCKETS`. A socket never extends its session, and it cannot: the browser's cookie only renews on a REST response. So step 11 must call `GET /session` from time to time while a page is open, or an editor making no REST call gets `4401` at the end of the lifetime. Tests about something else use `Fixed` in `tests/server.rs`.
- **Workspaces:** `WorkspaceStore` (`cadocs-store`) sits beside the other two stores. A method takes the actor and checks the role itself, through `authorize` in `sqlite/workspaces.rs`, inside the transaction for a write, so a route cannot forget it, and step 5 should do the same. The last owner check counts the enabled owners who would stay, as `delete_user` does. `PathParam<(String, String)>` reads two path parameters. `Page`'s rows come from `PageQuery::fetch` and `cut`. An invitation link is `<public url>/invite/<token>`, and step 11 must serve that page, which needs a login when `has_account` is true. `session::require_in_handler` is `require` for a route open to everyone. Changing `language` queues a reindex of every page of the workspace (`sqlite/search.rs`, `queue_reindex`). `purge_expired` deletes expired invitations. `GET /invitations/{token}` has no rate limit: a token cannot be guessed, so this only costs load, a hash and a read per request. Step 24 kept it so ([OPERATIONS.md](../OPERATIONS.md#security)).
- **Spaces:** `SpaceStore` (`cadocs-store`) sits beside the other stores. `authorize` in `sqlite/spaces.rs` resolves the role through `SELECT_SPACE` and `cadocs-core`, and turns a refusal into `SpaceNotFound` or `NotAllowed`: step 6 should use it, and pass `page_trashed` through a `Scope` of its own. `group_members` and group grants are read by resolution, and `PUT /grants` writes group grants, but nothing makes groups before V1, so tests insert them with SQL. The `purge_trash` job deletes a trashed space, with no route for it. `GET /workspaces/{ws}/spaces/trash` was added so that a restore has something to start from.
- **Pages:** `PageStore` (`cadocs-store`) sits beside the other stores, and `authorize` in `sqlite/pages.rs` resolves through `SELECT_PAGE`. `POST /spaces/{space}/pages` takes no title: the Yjs document holds it. `page_to_edit` is the check of a change that goes through a room. Nothing here publishes an event: step 9 hooks into `move_page`, `trash_page`, `restore_page` and `purge_page`. The server computes `position` from `after`, and a key only ever grows: a script alternating moves after one sibling inflates it, and it is also the tree cursor. Step 24 kept it without a cap: appending grows a key by a digit every 30 pages or so, so a cap would refuse long lists, and writers are trusted (ADR 0014). `tree` resolves the role per row, and deleting a user scans `pages` for its three `SET NULL` columns: step 23 should measure both. A tree has at most `MAX_PAGE_DEPTH` levels because of SQLite's limit on nested triggers.
- **Attachments:** `AttachmentStore` sits beside the other stores, and resolves roles through `SELECT_PAGE` joined to `attachment_refs`, with `download_allowed` from `cadocs-core`. The quota is checked again inside `create_attachment`, so two uploads at once cannot both pass it. `DELETE` removes the row with every reference, and the handler then deletes the file. The indexing job adds references with one `INSERT … SELECT` per id, on the writer, from the attachments of the page's workspace only: an orphan deleted first gives nothing, and one referenced first is kept by `forget_orphan`. `DELETE /attachments/{id}` removes the file for every referencing page, so since step 24 it needs `editor` on each of them, trashed ones included (`delete_allowed` in `cadocs-core`): before, an editor who pasted an id into a page of theirs could delete the file of a space they only read.
- **Search:** `SearchStore` (`cadocs-store`) sits beside the other stores. `search` takes an FTS5 expression, which only `cadocs-search` builds, and filters with `HAS_ROLE`, live pages and live spaces, so a viewer of one space never reads a title or an excerpt of another. `index_target` and `index_page` check no role: only the job calls them. `SqliteStore::with_reindex_delay` exists for tests; production uses `REINDEX_DELAY`, 5 seconds. Left open: a prefix typed past the end of a stem finds nothing until the word is whole (`deploym` misses `deployment`, stemmed `deploy`), since only stems are indexed.
- **Revisions:** `RevisionStore` sits beside the other stores. `append_updates` also records the flush's author in `revision_authors` and moves the `create_revision` job (`note_edit` in `sqlite/revisions.rs`), with an upsert on the partial index `jobs_dedup`, so it always wakes the worker. `latest_revision` and `add_revision` check no role: only the job and a checked restore call them. `readable_titles` answers the titles a renderer may show, and step 20's export should use it too. `SqliteStore::with_revision_timing` takes `CADOCS_REVISION_PAUSE_SECS` and `_MAX_SECS`; tests that wait for a job must not count `create_revision`, which waits 120 seconds by default (`run` in `tests/jobs.rs`). Left open: the comparison with the latest revision runs outside `add_revision`'s transaction, so a restore and a revision job at the same moment can store the same content twice, which is only noise in the history. A job queued before a page went to the trash still takes its revision. Every flush wakes the worker, even when it only moved the revision job later. A revision job that runs between a restore's rewrite and its last `keep` numbers the replaced content after the restored one; nothing is lost, and the next job records the restored content again.
