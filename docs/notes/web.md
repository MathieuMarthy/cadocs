# Web

What a change to the front end or its tests must know.

## Shell

- Svelte 5 with runes (ADR 0004). `App.svelte` holds every route in `resolve`, which also redirects: setup while no account exists, login with `?next=` without a session, back to `safeNext(next)` once there is one. A screen logs in by calling `signIn`, never by navigating. A logged-in person is sent home from `/login`, `/register` and `/forgot-password`.
- `lib/router.svelte.ts` catches clicks on same-site links. The server answers `index.html` for any path that is not a file (`assets.rs` lists the first segments that are not routes: add `s` with public shares).
- `lib/api.ts` keeps the CSRF token and sends every `unauthenticated` answer to `sessionEnded`. Only a real `POST /auth/logout` or a failed `refreshSession` drops the session: the server decides, not the screen.
- `lib/form.svelte.ts` holds a form's busy state and refusals. A `Form.run` inside an effect goes through `untrack`, since it reads `busy`.
- `Solo.svelte` for screens without a sidebar, `Shell.svelte` for the others. `Source.svelte` (source link, ADR 0010) must stay on every screen; the shell passes `withTheme={false}` since its user menu has the theme.
- The theme is `data-theme` on `<html>` over `light-dark()`, set before the first paint by `public/theme.js`: a file, since the CSP refuses inline scripts.
- Names users typed keep their case; only interface words are lowercase.
- Sidebar: sticky, only `.sidebar-scroll` scrolls, its `scrollTop` kept in a module variable since each screen mounts its own shell. Under 840px it is a drawer with `display: none` until `drawer-open`, so a test sees no `complementary` while it is closed.
- `.icon-button` sets `display` late in `base.css`, so a rule that hides one needs two classes (`.icon-button.drawer-button`).
- Logo: `.logo` caret is `aria-hidden`, so a test reads `cadocs`. `public/favicon.svg` carries its own colors. The README images in `docs/assets/` are captures of the real binary at 1280 by 640, 2x, both themes, seeded through `e2e/server.ts`: retake them when the shell changes visibly.
- Type checks: `tsc` skips `.svelte` files, and `svelte-check` needs TypeScript 5 or 6. Run it by hand after changing a component, from `web/`: `npx -y -p typescript@6 -p svelte-check@4.7.8 -p svelte@5.59.0 svelte-check --workspace . --tsconfig ./tsconfig.json`.

## Words

- Every string a person reads is `t(key, params)` from `lib/i18n` (step 34). `lib/i18n/en.ts` is the source, keys grouped by screen, `{name}` a parameter; an entry `{ one, other }` picks its form by `count` through `Intl.PluralRules` (none needs it yet). One key per sentence, never fragments glued together. Plain TypeScript, so the registry still loads under Node.
- `scripts/strings.ts`, run by `npm run build`, fails on words outside the catalogue: template text, attributes other than its list of code attributes, the strings an `{expression}` can show, and in code the strings given to `label`, `title`, `textContent` and the like, to `notify` or `setAttribute`, returned, or any two-word string elsewhere. `// i18n-ignore` on the line or the one before keeps one. It does not see a single word passed to a helper of our own (as `new CommandMenu(props, "pages")` was): review those.
- Text built when a module loads keeps the language of that moment: the registry's slash labels are getters, `defaultRoles()` and `stemmingLanguages()` are functions. Roles show through `roleName`, workspace languages through `Intl.DisplayNames`. Dates in words follow `currentLanguage()`; numeric dates follow `formatLocale()`, the browser's first locale, which a chosen language does not move (step 54). A key built from a value (`role.${role}`) that the catalogue lacks shows as itself.
- `useLanguage(user.language)` runs at boot and on a login, both awaited before the first screen, and in `updateUser` when the language changed (a session read again does not switch, which would remount an open page): the person's choice, else the first browser language the interface has, else English, and it sets `<html lang>`. The last call wins, whatever loads first. A logout keeps the language until the next boot.
- `t` is not reactive. `session.svelte.ts` stores the shown language in `app.language` once its catalogue loaded, and `App.svelte` is keyed by it, so a change draws the screens again and their local state is lost.
- `fr.ts` (step 54) is its own chunk. `Catalogue` fails the build on a key it lacks, and `scripts/i18n.test.ts` on a parameter or form that differs from English. A new key goes into both files. It puts a no-break space before `:`, `?` and `!`.
- Still English from the server: refusal messages (`describe` shows `error.message`), mails, slash command keywords. Field codes go through `field.<code>`, with the code itself as fallback.
- Playwright pins `locale: "en-US"`, since the interface follows the browser.

## Navigation

- `lib/nav.svelte.ts` holds a workspace's spaces, tree levels and events socket. `acquireNav` shares one `Nav` between screens and keeps the socket 2 seconds after the last leaves; a screen that calls it is keyed by workspace in `App.svelte`.
- A node is open exactly when its level is in `levels`, so events only refetch what shows. Templates read `loaded`, never `level`, which would write state while rendering. A page event refetches every loaded level of its space, 50 ms after the first of a burst, and bumps `versions` and `version`.
- Spaces load over REST at start, without waiting for a socket a proxy may block. Opening the socket and `resync` reload everything.
- Socket closes: `4401` ends the session, `4403` and `4404` refresh it, anything else retries with backoff, refreshing the session every third failure.
- Tree drags carry `application/x-cadocs-page`. A drop on the top quarter of a row goes before it, the bottom quarter after, in between under it, on a space at the end of its root.
- Tree actions are `display: none` until the row is hovered or focused, so tests point at the row first (`press` in `navigation.spec.ts`) or use `includeHidden`. An open menu keeps them through `:has([aria-expanded="true"])`, or moving focus into the menu would remove it.
- `lib/actions.ts` holds what the tree and the page's top bar share (`copy`, `pageLink`, `trashPage` with its `undo`). `trashPage` leaves a page shown under the trashed one for its parent, or `/w/<slug>`; the page view tells it what shows through `showPage([...ancestors, id])`. `undo` goes back, bumping `reopened` (part of the page view's key) to mount it again.
- Left open: no keyboard way to move a page; no `rename` in the tree menu (`PATCH /pages/{id}` takes a title); trashing an ancestor while on the history route leaves that history on screen; `open the parent page` can land on a trashed page when an ancestor further up was trashed.

## Page view

- `routes/Page.svelte` and `editor/collab.ts` load on demand, so a login does not download TipTap. The page reads `GET /pages/{id}` before opening the socket, and again every 3 failed connections, since a socket cannot read why an upgrade failed. Only `401` and `404` stop it. Another REST failure still shows the editor, in a shell with no workspace, and reads again every 2 seconds.
- `ancestors` from that read fill the breadcrumb and expand the tree once per mount (`revealed`). While the first read is pending, the shell shows `lastWorkspace`, so a click in the tree does not flash. A re-read on a change to its space fires only for a version not yet seen (`seen`), or a revoked page showed `page not found` instead of `access revoked`. That re-read also leaves a `404` to the open socket (`check({ socketTells: true })`), since REST answers `404` alike for a trashed page and a lost one, while the socket closes with `4404` or `4403`: without it, a `page.trashed` event turned `page deleted` into `page not found` (CI, after v0.2.0). An editor stopped on content it cannot show (`stale`) has no socket left, so its reads still conclude. No read replaces a `gone` already set.
- A page opened by its address has its space open: a test must not click the space after it, which would close it.
- `disableBc` is on, so two tabs of one browser really go through the server. Awareness holds `user: { id, name, slot }`, `slot` 1 to 3 picking the presence color. Avatars show from two people.
- The title is a `textarea` bound to `Y.Text` (`editor/title.ts`), grown to its text and kept on one line. Tests read it with `getByLabel("page title")`.
- A page whose access ends while it reconnects after a `4409` shows `page not found`, as REST answers `404`. Tests that revoke after a role change wait for `synced … read only` first.
- A screen's `status` role is not unique (the tree has one while loading): tests look in `banner` or `main`. The notice's `status` exists only while there is a notice, mounted once in `App.svelte`.
- A `4409` reads the role over REST before the socket reconnects, and the new socket's mode is not reported to the client: a second role change landing between that read and the reconnection leaves the editor in the first one's mode (the server still refuses the writes). Tests that change a role twice wait for `synced` between the two (`settings.spec.ts`, group grant test).
- `duplicate` in the page menu shows for anyone who writes in some space, and opens `DuplicatePage.svelte` above the title: a space picker over the spaces the user edits, its own space first. In its own space the copy goes right after the page (`{ parent_id, after }`), elsewhere last at the root (`{ space_id }`); the screen then opens the copy. There is no `<dialog>` in the app yet, so the form takes the `.banner` box.
- Left open: presence counts awareness clients, so one person in two tabs shows two avatars; edits typed between a demotion and its `4409` stay in that tab until a reload.

## Editor

- `editor/registry.ts` is the only list of what the editor knows: each entry brings its extensions and slash commands. StarterKit stays as the core with every registry block turned off: add a block as an entry, never through StarterKit. Node names are TipTap's defaults. A new block needs `npm run schema`, or `npm run build` fails ([content notes](content.md)); the registry must stay importable under Node, so no DOM and no `$state` at module level.
- A new block extension with Markdown input rules goes through `quietInSource()`, or its shortcuts fire inside written-out sources.
- `editor/menu.ts` is the command menu, used by the slash menu (`slash.ts`) and the `[[` picker, drawn in plain DOM, focus left in the text: a `listbox` (`commands`, or `pages` for the `[[` picker) with `option`s. Off in code blocks and for readers. A slash opens it only at the start of a block or after a space; a command can take `when`. The command removes the typed query in its own transaction first: `prosemirror-tables` commands in one chain read positions from before the chain.
- The `[[` picker reads up to 1000 recent pages and filters titles in the browser, kept 10 seconds.
- Read-only follows the role of each `GET /pages/{id}` answer. `4409` makes the editor read-only at once, then reads again. `enableContentCheck` is on: a `contentError` destroys the provider and shows the `reload` banner (`editor.spec.ts` writes an unknown `futureBlock` to test it). A `4426` close (another release, step 56) stops the editor the same way with `page.outdated`: the provider is made with `connect: false` and connects once `editor.schema` gives the fingerprint. `e2e/editor` fakes a stale tab by rewriting `schema=` in an init script that wraps `WebSocket`.
- Markdown source (ADR 0018, `editor/source.ts`): a block's source is written into it when the caret reaches its marker, read back when it leaves. A remote change can rebuild the document, so the block is found again from the caret. A block not written out is read on leaving only if this tab changed it (`touched`) and it is not code. A hint is not drawn on a block whose text already reads as its source. `syncCaret` reads the selection before every key.
- Math and diagrams (step 43, `editor/math.ts`): code blocks in `math` and `mermaid` get a `.code-preview` widget after them, keyed by language and source so only an edit draws again; a read-only editor hides their `pre` by CSS (`:has(+ .code-preview)`). `inlineMath` is an atom drawn by KaTeX; `$x$` typed makes one (no space inside the dollars, as Markdown), and a click, or the slash command's empty insert, swaps it for a `formula` field (ProseMirror's own click handling is stopped there): Enter or a blur stores, Escape keeps the old source, empty removes it. The arrows only select it on their way past, so the field never traps the keyboard. KaTeX (with its CSS) and Mermaid are dynamic imports, so their chunks load on the first formula or diagram (`e2e/math` checks no request before). Mermaid runs in `strict` security, its theme read once from `data-theme` or the system. A diagram waits 300 ms and draws only if its box is still shown, so typing draws once per pause. A source Mermaid refuses shows `diagram error`, and readers then see the source too.
- Heading numbers and the code language are decoration attributes (`data-number`, `data-language`) shown by `::before`. The language changes only through the fence line.
- Blocks of our own: `callout` (`kind`), `details` (`persist` off, each tab opens it for itself), tables with `resizable` on (step 76: a writer drags a column's edge, stored as each cell's `colwidth`; `prosemirror-tables` checks `view.editable` on each move, so readers cannot drag. Its plugin is only made when the editor starts editable, so `collab.ts` starts every editor editable and `applyMode` sets the real mode at once), `pageLink` (inline atom with `id`; the title is read over REST and cached per open page, so a rename shows on the next page opened), `tableOfContents` (atom, drawn from the headings), `plugin` (ADR 0016, shows its `text` dashed), `image` and `file` (`attachments.ts`).
- Table controls (`editor/table.ts`): two `+` buttons in `.table-frame`, shown only on hover in an editable editor, so tests hover first; a right click opens a `table` menu with the classes of `Menu.svelte`.
- Uploads go one at a time (`uploads.ts`). A paste test builds its `DataTransfer` in the page (`attachments.spec.ts`). A file block shows its size from a `HEAD` on the download, not stored in the document.
- StarterKit's `TrailingNode` adds a paragraph in every tab when a page ends on another block, readers too, so two writers can add two. Not fixed: without it, nothing can be typed below a final block. Tests find it with `:scope > p`.
- Left open: links to pages cannot be dragged from the tree.

## Comments

- Step 38. `lib/comments.svelte.ts` holds the REST calls and `PageComments`, the threads of one page: Page.svelte makes it, the editor draws it, `components/Comments.svelte` (the panel) lists it. Everything goes through `PageComments`, which calls `draw()` after each change of threads, picked thread or draft: no effect pushes to the editor.
- `editor/comments.ts` is a plugin added in `collab.ts`, not a registry entry, since it adds nothing to the schema. An anchor is `absolutePositionToRelativePosition` of `@tiptap/y-tiptap` with the `ySyncPluginKey` state, encoded and base64'd. Never TipTap's `getYAbsolutePosition`, which turns a lost position into `0`.
- Resolving in `apply` is right only for a change from Yjs (it carries `ySyncPluginKey` meta): a local edit reaches Yjs after `apply`, so the binding's mapping is stale then. Local edits map the decorations, and a meta transaction resolves them all again 200 ms later.
- An anchor is lost when a position does not resolve or its range holds no text: positions on deleted text still resolve, to one point. `found` stays `null` until the first sync, or every anchor would look lost against the empty document.
- The `[n]` counter is an empty widget whose text is CSS (`data-count`), placed in the right gutter by `position: absolute` with no `top`. `.tiptap` is `position: relative` for it. Text read by tests stays the document's.
- A read-only editor (a `commenter`) still follows the DOM selection, so the anchor comes from `editor.state.selection` for every role. It is taken when the composer opens, then shown as a highlight with no counter (`draft`).
- `Nav` bumps `comments` per page on a `comment` event, and `reloads` in `reloadAll` (socket open, `resync`): the page reads its threads again, 50 ms after the first of a burst. The panel is a `region` named `comments`, never an `aside`, since tests find the sidebar as the only `complementary`.
- Source mode (ADR 0018) keeps a heading's anchors: `setNodeMarkup` keeps its Yjs text items (`a writer's caret passing the marker…`). Lists, quotes and dividers go through `replaceWith` and are not tested: an anchor inside one may be lost when its source is written out and read back.
- A role change that keeps the socket's mode (viewer to commenter) closes nothing, so the page view reads its role again when the space list's role differs from the one it holds, and the panel follows.
- The body is plain text with mention tokens (step 39, [API.md](../API.md#comments)), never HTML nor Markdown: the smallest form that carries mentions with no rendering to make safe. `components/CommentBody.svelte` cuts it with `lib/mentions.ts` and shows text as text, a user as `@name` and a page as a link with its title, each read when shown (`lib/people.ts`, `titleOf` of `editor/pagelink.ts`). Its markup holds no whitespace between pieces, since `white-space: pre-wrap` would show it.
- The three fields are `components/CommentField.svelte`, a small TipTap editor (StarterKit with only paragraphs, text, hard breaks and history, plus `mention`, `pageLink` and their pickers), not a `textarea`: an atom keeps a mention whole, which text standing for a name could not. It reads `value` once, when mounted, and writes the body back on each change (`bodyOf`, `contentOf`): the panel remounts the reply and edit fields with `{#key opened}`, bumped by each `open()`, so picking edit again on a form already open starts from the comment's text. `bodyOf` drops a pasted node whose id the grammar would not read back. Tests find it as a `textbox` by its label, `fill` it, and read it with `toHaveText`, not `toHaveValue`. An empty body is refused by the server (`body: required`), as nothing in the browser checks it now.
- The panel scrolls a picked thread into view once per pick, when a read brings it (`PageComments.version`): the read a new comment waits for can be dropped as older than the one its `comment` event starts.
- Left open: no keyboard shortcut to comment; a click on a highlight already picked does not scroll its thread again; the panel shows at most 1000 threads.
- A page link inside a composer opens in another tab (step 65, `PageLink.configure({ newTab: true })` in `CommentField`): its `target` makes the router leave it to the browser, so the draft stays.

## Mentions

- Step 39. `editor/mention.ts` holds the `mention` node (in the registry, so in the schema) and `MentionPicker`, which `collab.ts` and `CommentField` add with the workspace, as `PagePicker` is added. `@` opens it after a space or at the start of a line only (Suggestion's default prefix), so an address with `@` inside opens nothing. The picker is a `listbox` named `people`.
- A node view needs the workspace for the name, and the node comes from the registry with no options: it reads the picker's getter from `editor.storage.mentionPicker`, and waits while it answers `null` (the page's row not read yet). An editor without the picker (the schema script) shows no name.
- `lib/people.ts` reads `GET /workspaces/{ws}/members`, at most 1000, kept 10 seconds and shared by every mention, picker and comment. Someone not in the list shows `@someone`, as public pages show everyone. Left open: a workspace of more than 1000 members names only its oldest accounts.

## Other screens

- Icons: `components/icons.ts` holds the Lucide shapes of the design system, drawn by `Icon.svelte` inside one `svg`, and `iconMarkup` for plain DOM. Add one by copying its shapes from `lucide-static` 0.460.0, never its attributes. `IconButton` takes the verb as `title` and the full label as `aria-label`.
- `Menu` is a `popover="manual"` in the top layer, placed from its button and closed by a press outside, a scroll or a resize. Opened by keyboard it focuses its first item, by pointer the menu itself.
- `Confirm` takes `icon` and `danger`. The notice focuses its `undo` and restarts its timer.
- Account: two forms named by their headings (`profile`, `email and password`), reached with `getByRole("form", { name })`; the email sits with the password, since the server asks the current password for it. Tests log out through the user menu (`logOut` in `shell.spec.ts`).
- Settings: sections are `section`s named by their `h2`, reached with `getByRole("region", { name })` (a name matches by substring unless `exact`). Row role pickers are plain `select.select` with an `aria-label`, acting on change. A grant change `PUT`s every other grant as it was, groups included. Nobody changes their own workspace role: they `leave`. `access.changed` refreshes the session, whose workspaces carry the role. Groups (step 36) are `components/Groups.svelte`, a `groups` region of the workspace settings: a group's members open under its row with the button `members of <name>`, whose pickers and fields are named after the group (`add to <name>`, `name of <name>`, `remove <member> from <name>`), so no new label holds `members` or `access` as a substring. In the space settings, groups are rows of the `access` region above the members, `access of the group <name>`; the screen reads the members of each granted group to show `<role> through <groups>` under a member, and calls `nav.loadSpaces()` after any group grant change, since the user's own role may follow it.
- Search (`routes/Search.svelte`): the address holds the query, so a reload or link shows the same results. Excerpts render as text with `<mark>`, never `{@html}`. `Ctrl K` goes there. Left open: the design system's command palette.
- History (`routes/History.svelte`, `/?page=<id>&history`): the server's escaped HTML shows with `{@html}` inside `.tiptap.revision-content`; `base.css` covers the task list and callout markup that differ from TipTap's. A `compare with` picker diffs two revisions in the browser (`lib/diff.ts`): top-level blocks of the escaped HTML, longest common subsequence, changed blocks wrapped in `.diff-add` and `.diff-del`. There is no route for the current content, so the latest revision stands for the current page.
- The print stylesheet is at the end of `base.css`.
- Motion (`lib/motion.ts`): `unfold` and `appear` read `--motion-duration` at each run; it is `0ms` under `prefers-reduced-motion`, and Svelte then animates nothing. A tree level's `{#if}` waits for `loaded`, or `slide` measured 0. During an outro the element stays in the page, `inert`. A test that scrolls the tree waits for `document.getAnimations()` to be empty.
- Mail screens show only when `mailFeatures()` (`GET /auth/setup`, read when a screen mounts) says so; with no relay their paths show `not found`. Forgot password and registration show the same notice for every address. Login keeps the password in memory for the second factor's code form. Account compares the address `PATCH /me` answers with the one typed to know whether a code was mailed.
- The authenticator app (step 47) is the `authenticator app` region of the account, shown with or without a relay. Its setup takes the password, then shows the QR code (`uqr`, imported on demand, drawn as one SVG path in a light box in both themes), the key in `<code>`, and a `code from the app` field; the ten recovery codes show once, in a `recovery codes` list, until `done`. One form under the app's `current password` holds `new recovery codes` and `turn off`, told apart by the submitter's `value`. Login shows `app or recovery code` when the server names `totp`. `e2e/totp.spec.ts` computes codes with Node's `crypto`, apart from the server's code.
- A wrong code is a `400` the field shows as `wrong`. A `401` on a second factor's form (step 65) means the password changed or the account went meanwhile: the login goes back to the email and password, the email kept, and says `this login no longer works`.
- Share dialog (step 46): `components/Share.svelte`, mounted by `Page.svelte` from the `share publicly` item of the top bar menu, which shows only while the page's role is `editor` or `admin` (`canEdit`); a role that drops closes it. It is the first modal: a native `<dialog>` opened with `showModal()` in `onMount`, so the browser traps focus, closes on Escape (its `close` event unmounts it) and gives focus back to the menu button. Everything outside is inert, the notice included, which then leaves the accessibility tree: the dialog says `link copied` and `link revoked` in its own `status` line rather than through `notify`. The list is `collect` of `GET /pages/{page}/shares`; an expiry is the start of the day after the date picked, in local time (`endOfDay`), and shows as `until <that date>`. A `404` on revoke counts as done (another tab revoked it). The form works before the list lands, so the list merges what was created meanwhile and drops what was revoked meanwhile. `say` empties the status line, waits a `tick`, then writes, or the same result twice changes no text and is not announced. A role that drops unmounts the open dialog without `close()`, so `Page.svelte` gives focus back to the menu button (`.page-actions`) itself.
- Checkboxes are `label.check` with an `appearance: none` input (`base.css`), `auto` again under `forced-colors: active`, which drops the background and shadow that show the state; tests reach them with `getByRole("checkbox", { name })`.

- Bulk import (step 53): `components/BulkImport.svelte`, under a space's row from `import a zip of pages` in its menu. One select per level picks the parent, each listing at most 1000 pages (`collect`). `bulkImport` in `lib/api.ts` polls the job every second while the form stays busy.

## Browser tests

- `web/e2e/` runs the real binary on its own port and data folder (`server.ts`; `CADOCS_BIN` picks another binary, and `../target/debug/cadocs` reads `web/dist` at run time for a quick loop). `TestServer` runs first-run setup, `page(name)` creates a page per name, and `call`, `invite`, `addMember` do what a test does not go through the interface for.
- Playwright reads `CHROMIUM_PATH`. Helium in a new process can stall every request 5 seconds or more, then load the page twice: `expect.timeout` is 30 seconds.
- `compat.test.ts` uses `node:test` with the real `yjs` and `y-websocket` (Node 22.18 or later). Node's `WebSocket` sends the cookie through `webSocketClass()`.
- `e2e/editing.ts` holds the two-browser fixture and editor helpers. A paragraph's text holds the label of a remote caret: read it with `bodyLines` or `expectText`. A task's text is in `ul[data-type="taskList"] > li > div`. `newLine` uses the keyboard only. A code block ends on a third Enter.
- Open a second tab of a logged-in browser with `browser.newContext()` and `logIn`.
- A rename reaches `pages.title` at the next flush, about 540 ms later: a test that renames over REST and then reads the tree, recent pages or the picker calls `server.titleStored(id, title)` first.
- An open client resends its whole document when it reconnects, so a test about the disk has no client left when the server comes back.
- Do not `goto("about:blank")` before another `goto`: the second navigation can abort.
- `e2e/relay.ts` is a plain text SMTP relay in Node; `relay.message(n)` waits for the n-th. Codes match `/^ {4}(\d{6})$/m`.
- `e2e/shares.spec.ts` proves the public policy with `page.route`: it serves the real answer with scripts added, once with its headers and once without the policy, so the control shows the injection would run. `page.evaluate` still works under `script-src 'none'`.
- `e2e/shares.spec.ts` also drives the share dialog: `dialog(page)` is `getByRole("dialog", { name: "public links" })`, its links the `listitem`s of the list of that name. A date field takes `YYYY-MM-DD` through `fill`; the past-date test clears `min` in the page to reach the server's refusal.
- `e2e/revisions.spec.ts` overrides the `server` fixture with a 1-second revision pause.
- `screens.spec.ts` saves a screenshot of each screen in both themes in `test-results`.
- `e2e/comments.spec.ts` selects through a DOM range (`select`): a mouse drag in Chrome widens to whole words and trailing spaces.
- Known flaky, with Helium, not regressions: `a source written out in one browser is left alone by a caret passing in the other` (`editor.spec.ts`, about one run in four), `a page moves to trash from its menu by keyboard alone…` (`navigation.spec.ts`, 3 to 5 runs in 10).
