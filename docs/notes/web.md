# Web

What a change to the front end or its tests must know.

- **Shell:** Svelte 5 with runes (ADR 0004), mounted on `body` by `main.ts`. `App.svelte` holds every route in `resolve`, which also does the redirects: setup while no account exists, login with `?next=` without a session, back to `safeNext(next)` once there is one. So a screen logs in by calling `signIn`, and never navigates for it. `lib/router.svelte.ts` has no dependency: it catches clicks on same-site links, and the server answers `index.html` for any path that is not a file (`assets.rs`, which lists the first segments that are not routes: add `s` with public shares). `lib/api.ts` keeps the CSRF token and sends every `unauthenticated` answer to `sessionEnded`, so a screen need not handle a lost session. Only a `signOut` after a real `POST /auth/logout` or a `refreshSession` that failed may drop the session: the server decides, not the screen. `lib/form.svelte.ts` holds a form's busy state and refusals, and shows a field's code with spaces (`too short`). Screens without a sidebar use `Solo.svelte`, the others `Shell.svelte`. `Source.svelte` has the source link and the theme button, and must stay on every screen (ADR 0010): the shell passes `withTheme={false}`, since its user menu has the theme. `vite.config.ts` builds the link from the commit, or from the tag without Git. The theme is `data-theme` on `<html>`, over `light-dark()` in the tokens, set before the first paint by `public/theme.js`, a file because the CSP refuses inline scripts.
- **Type checks:** `tsc` skips `.svelte` files, and `svelte-check` needs TypeScript 5 or 6 while the project has 7, so it is not a dependency. Run it by hand after changing a component: `npx -y -p typescript@6 -p svelte-check@4.7.8 -p svelte@5.57.3 svelte-check --workspace . --tsconfig ./tsconfig.json` from `web/`.
- **Left for later steps:** Moving a page has no keyboard way yet, only drag and drop. The tree menu has no `rename` yet, which the design system lists: `PATCH /pages/{id}` already takes a title. Presence counts awareness clients, so one person in two tabs shows two avatars, though awareness now carries the user's `id` to count by. A code block's language is changed only through its fence line (ADR 0018), there is no picker. Edits typed in the instant between a demotion and its `4409` stay in that tab, which the server no longer accepts them from, until a reload. StarterKit's `TrailingNode` adds a paragraph in every tab when a page ends on another block, readers included: a reader's copy then differs from the server's by that paragraph, and two writers can add two. Not fixed: turning it off leaves no way to type below a final block. Links to pages cannot be dragged in from the tree yet, and a rename shows in a link only once the page is opened again.
- **Navigation:** `lib/nav.svelte.ts` holds a workspace's spaces, tree levels and events socket. `acquireNav` shares one `Nav` between the screens, since each mounts its own `Shell`, and keeps the socket 2 seconds after the last one leaves. A screen that calls it is keyed by workspace in `App.svelte`. A node is open exactly when its level is in `levels`: closing one drops the levels under it, so events only refetch what shows, and templates read `loaded`, never `level`, which would write state while rendering. A page event refetches every loaded level of its space, 50 ms after the first of a burst, and bumps `versions` and `version`, which the trash and recent pages watch. The spaces load over REST at `start`, without waiting for a socket a proxy may never let through. Opening the socket, and `resync`, reload everything, and a space whose role changed reads its levels again, since each row carries the role. Tree drags carry `application/x-cadocs-page`, so a dragged file or text is ignored. `4401` ends the session, `4403` and `4404` refresh it, and anything else retries with backoff, refreshing the session every third failure. A drop on the top quarter of a row goes before it, on the bottom quarter after it, in between under it, and on a space at the end of its root. Logging out now closes the events socket, so the shell goes to login at once.
- **Page view:** `routes/Page.svelte` and `editor/collab.ts`, loaded on demand, so a login does not download TipTap. It sits in the shell (`bare`, with the status and presence in the `end` snippet), placed in its workspace by the `GET /pages/{id}` it reads first. A REST failure that is not `401` or `404` still shows the editor, in a shell with no workspace (`guess={false}`), and the page reads itself again every 2 seconds until it knows where it lives. A change to its space reads it again, so a move updates the breadcrumb, and a read that finds it gone destroys the editor. The tree marks the page the address shows. A screen's `status` role is no longer unique, as the tree has one while loading: tests look for it in `banner` or `main`. `?page=<id>` picks it. It reads `GET /pages/{id}` before opening the socket, and again every 3 failed connections, because a socket cannot read the status of a failed upgrade. Only `401` and `404` stop it. `4401` goes to login, `4403` and `4404` replace the page with a message. `disableBc` is on, so two tabs of one browser really go through the server. Awareness holds `user: { id, name, slot }`, from the session, where `slot` (1 to 3) picks the presence color. The title is a plain input bound to `Y.Text` in `web/src/title.ts`.
- **Shell layout (step 12b):** the sidebar is sticky at the window's height, and only `.sidebar-scroll` (the tree) scrolls; its `scrollTop` lives in a module variable of `Shell.svelte`, since every screen mounts its own shell. Under 840px it is a fixed drawer with `display: none` until `drawer-open`, so a test sees no `complementary` while it is closed. A change of address closes it, Escape closes it unless a menu is open, and a press outside it or its menus closes it. The footer is a `Menu` with `text` (the user's name, not lowercased), whose items are account, `theme: <current>` and log out: tests log out through it (`logOut` in `shell.spec.ts`), but `Invite.svelte` keeps its own `log out` button. The breadcrumb takes `crumbs: { label, href? }[]`, and `crumbWorkspace={false}` on the workspace home, account and admin. `admin` is the only row left under `settings`, so the group shows only to instance admins. Names users typed (workspaces, spaces, pages) keep their case everywhere; only interface words are lowercase.
- **Page view placement:** `GET /pages/{id}` answers `ancestors`, which the breadcrumb links and which the page expands in the tree once per mount (`revealed`), so a user who collapses it later is not overridden by the next re-read. The selected row scrolls into view through an attachment in `TreeLevel`, and again when the drawer opens. While the first read is pending, the page shows a shell on `lastWorkspace` (the tree that showed last) with `loading…` in `main`, so a click in the tree does not flash. Once a read answered or the editor shows without one, only the page's own workspace is used. The re-read on a change to its space only fires for a version it has not seen (`seen`): an effect that runs again for another reason, as after expanding the tree, used to read a revoked page first and show `page not found` instead of `access revoked`. A page opened by its address now has its space open: do not click the space in a test after it, which would close it.
- **Icons and menus:** `components/icons.ts` holds the Lucide shapes of the design system's table, which `components/Icon.svelte` draws as strings with `{@html}` inside one `svg` that carries the stroke settings. Add an icon by copying its shapes from `lucide-static` 0.460.0, never its attributes. `IconButton` takes the verb as `title` and the full label (`new page in Deploy`) as `aria-label`. `Menu` is the `ellipsis` button and its `role="menu"`, a `popover="manual"` in the top layer so a scrolling sidebar does not clip it, placed from the button's box when it opens and closed by a press outside, a scroll or a resize. Its items are `tabindex="-1"` and take focus from the arrows and the pointer. Opened by Enter or Space (a click whose `detail` is 0), it focuses its first item; opened by the pointer, it focuses the menu itself, so no row shows inverted before the pointer reaches it (in the dark theme that row merged with the light border and shadow). A `space-1` padding keeps the active row inside the border. A link item closes the menu without taking focus back. `lib/notice.svelte.ts` holds the one notice, shown by `Notice.svelte`, mounted once in `App.svelte`, and its `status` region exists only while there is a notice, since tests read a screen's single `status`. Mounted there so a screen that changes under it (a trashed page turning into `page deleted`) keeps it. The notice focuses its `undo` and restarts its timer, since that focus is not the reader holding it. An `undo` that restores the page on screen bumps `reopened` (`lib/router.svelte.ts`), part of the page view's key, to mount it again. `Confirm` takes an `icon` and `danger` for a final action in a list row.
- **Tree actions out of layout:** `display: none` until the row is hovered or holds focus, so `getByRole` does not see them: tests point at the row first (`press` in `navigation.spec.ts`) or count with `includeHidden`. An open menu keeps them displayed through `:has([aria-expanded="true"])`, because moving focus from the button to the first item first blurs the button, which would remove the menu with its row and drop focus on `body`.
- **Browser tests:** Playwright reads the browser path from `CHROMIUM_PATH` through `executablePath`, and uses its own Chromium when unset. Any Chromium-based browser works.
- **Slow browser start:** Helium, in a new process, can stall every request for 5 seconds or more, static files too, and then load the page a second time. It does not come from the server, and `requestfinished` shows it. A page opens its socket after three round trips, so this now falls before the socket, and `expect.timeout` is 30 seconds. For a quick loop, `CADOCS_BIN=../target/debug/cadocs` reads `web/dist` at run time and needs no release build.
- **End-to-end tests:** `web/e2e/` runs the real binary, on its own port and temporary data folder (`server.ts`, `CADOCS_BIN` picks another binary). `TestServer` runs first-run setup on the first `session()`, and `page(name)` creates a page per name, so tests keep naming their rooms. Node's `WebSocket` sends the cookie through `webSocketClass()`, passed as `WebSocketPolyfill`, and a browser gets it from `addCookies`. `compat.test.ts` uses `node:test` with the real `yjs` and `y-websocket`, and needs Node 22.18 or later for type stripping and `node:sqlite`. `browsers.spec.ts` uses Playwright, with two real browser processes. `shell.spec.ts` covers the shell, `navigation.spec.ts` the tree, the trash and recent pages, `fixtures.ts` holds what the specs share, and `TestServer` gives them `call`, `invite` and `addMember` for what the test does not go through the interface for. Playwright's `dragTo` drives the native drag and drop of the tree, and `targetPosition` picks the zone. An open client resends its whole document when it reconnects, so a test about the disk must have no client left when the server comes back. A paragraph's text holds the label of a remote caret: read it with `bodyLines`. Do not `goto("about:blank")` before another `goto`: the browser sometimes commits it twice, which aborts the next navigation.
- **Screens (step 12c):** `lib/actions.ts` holds what the tree and the page's top bar share (`copy`, `pageLink`, `trashPage` with its `undo`), so both say `link copied` and `moved to trash`. `NewSpace.svelte` is the space name form, opened by the `plus` beside the `spaces` label (`managesSpaces`: workspace owner or admin) and by the empty home; Escape in its field closes it. `Time.svelte` shows a date as `5 minutes ago`, the exact one in `title`, and refreshes every 30 seconds. The page title is a `textarea` that `editor/title.ts` grows to its text and keeps on one line (a pasted line break becomes a space); tests still read it with `getByLabel("page title")` and `toHaveValue`. Avatars show only from two people, so a test alone on a page sees no `.avatar`. The account has two forms named by their headings (`profile`, `email and password`): tests reach them with `getByRole("form", { name })`. The server asks the current password for a new email too, so the email lives in the second form. Administration actions are in a `more actions for <name>` menu per user; the current admin's menu only has `new reset link`, and `delete` asks again inline with a `danger` button. `Confirm` with `danger` and no `icon` shows both buttons in `danger`. `screens.spec.ts` covers this step, and its theme tests save a screenshot of each screen in `test-results`.
- **Two-class overrides:** `.icon-button` sets `display`, and comes late in `base.css`, so a rule that hides an icon button needs two classes (`.icon-button.drawer-button`). The drawer buttons showed on wide windows until step 12c for this reason.
- **Editor (step 14):** `editor/registry.ts` is the only list of what the editor knows: each entry brings its extensions (which carry the Markdown input rules and keys) and its slash commands, and `collab.ts` builds the editor from it. StarterKit stays as the core, with every block the registry owns turned off, so add a block as an entry and never through StarterKit. Node and mark names are TipTap's defaults (`taskList`, `taskItem`, `codeBlock`, `horizontalRule`, `link`...), which step 16 compares with Rust. `editor/slash.ts` is the command menu, drawn in plain DOM by `@tiptap/suggestion`, with focus left in the text: the list is a `listbox` named `commands` with `option`s and `aria-selected`, and its `commands · N` header sits outside it. It is off in code blocks and for readers. `[text](url) ` makes a link only for an address `isAllowedUri` accepts. The role from `GET /pages/{id}` sets `setEditable`, read-only until a read answers; `4409` makes the editor read-only at once, then reads the page again, and every successful read sets the mode, even to the same value; the provider reconnects alone. Readers see `· read only` after the status. `enableContentCheck` is on: a `contentError` destroys the provider and the document, makes the page read-only, and `Page.svelte` shows the `alert` banner with `reload`. `editor.spec.ts` writes an unknown `futureBlock` element from Node to test this.
- **Markdown source (ADR 0018):** `editor/source.ts` writes a block's Markdown source into it as text when the caret goes onto its marker, and reads it again when the caret leaves. The block being edited is a plugin position, mapped through local steps; a remote change (`ySyncPluginKey` meta `isChangeOrigin`) may rebuild the document, so the block is then found again from the caret, which never leaves it without a read, if it kept its type. A block not written out is read on leaving only if this tab changed it in that visit (`touched`) and it is not code. A new block extension with Markdown input rules goes through `quietInSource()` in the registry, or its shortcuts fire inside written-out sources. Heading numbers and the code language label are node decoration attributes (`data-number`, `data-language`) shown by `::before`. `syncCaret` reads the page's selection before every key: a test pressing `Home`, `End` or `Control+End` then another key relied on luck before. Tests that leave the last block find the `TrailingNode` paragraph in their `p` lists.
- **Editor tests:** a block's text holds the name on a remote caret, so read it with `expectText` (`editor.spec.ts`), which also survives the second load of a fresh Helium. TipTap's task item puts a visually hidden label inside its `label`, so read a task's text from `ul[data-type="taskList"] > li > div`; its `li` has no `data-type`. A code block ends on a third Enter at its end. Under four workers, a click before `Control+End` could land after it and put the next block inside the last one: `newLine` uses the keyboard only, and `command` waits for the menu to show one option and to close. `a read older than a demotion…` failed once in a full run and passed 12 times in a row under load after that: if it comes back, look first at whether the held read is really the one the rename triggers. Open a second tab of a logged-in browser with `browser.newContext()` and `logIn`, since `browser.newPage()` pages own their context.
- **Settings (step 13):** `routes/WorkspaceSettings.svelte` (`/w/{slug}/settings`) and `routes/SpaceSettings.svelte` (`/w/{slug}/settings/{space}`), reached from the sidebar's `workspace` row under `settings` (shown whenever a workspace is) and from the `settings` item every space's menu now has, readers included; `open the trash` stays for editors. Every member sees both screens: the controls show only to who may use them, by `managesWorkspace` and the space's `role`. Sections are `section`s named by their `h2`, which tests reach with `getByRole("region", { name })`; mind that a name matches by substring unless `exact`. Role pickers in rows are plain `select.select` with `aria-label` (`role of Grace`, `access of Grace`) and act on change; `components/Select.svelte` is the labelled one for forms. Nobody changes their own workspace role or removes themself from the members list: they `leave`. A grant change sends `PUT` with every other grant as it was, groups included, and the `""` option means no grant, so the default role. `lib/roles.ts` holds the roles, languages and the `Member` shape. `access.changed` now also refreshes the session, whose workspaces carry the caller's role, so a promoted user gets `new space` without a reload. A `Form.run` called inside an effect goes through `untrack`, since it reads `busy`. Trashing a space goes home with `moved to trash` and an `undo`; the workspace settings list trashed spaces to their admins with `restore`.
- **Blocks of step 15:** node names, for step 16. `callout` (`kind`: `note`, `warning` or `danger`, content `block+`; Markdown has no callout, so step 20 writes a GitHub alert, `> [!NOTE]`, `[!WARNING]`, `[!CAUTION]`). `details` with `detailsSummary` and `detailsContent` (TipTap's toggle, `persist` off, so no `open` attribute: each tab opens it for itself). `table`, `tableRow`, `tableHeader`, `tableCell` (cells carry `colspan`, `rowspan`, `colwidth` and `align`; `resizable` is off, so `colwidth` stays `null`). `pageLink`, inline atom with only `id`: the title is read over REST when shown and cached for the open page (`forgetTitles` on each open), so a rename shows on the next page opened, and an unreadable page shows `page not found`, as REST answers `404`. A renderer must look the title up, with the reader's permissions. `tableOfContents`, a block atom with no attribute, whose list the browser draws from the headings (`headingNumbers`, exported from `source.ts`). `editor/menu.ts` is the command menu, shared by the slash menu and the `[[` page picker (a `listbox` named `pages`), which reads up to 1000 recent pages of the workspace and filters titles in the browser until search (step 18) answers instead. A slash command can take `when` (the table commands only show in a table). The slash menu allows spaces (`add row below`), and a query with a space that finds nothing closes it. The command removes the typed query in its own transaction, then applies: `prosemirror-tables` commands in the same chain read positions from the document as it was before the chain and added a column twice.
- **Plugin node and schema export (step 16):** `PluginBlock` in `blocks.ts` is the `plugin` envelope of ADR 0016, an atom that shows its `text` dashed (`.plugin-fallback`) since no plugin runs yet. A block added to the registry needs `npm run schema`, or `npm run build` fails: see [content notes](content.md). `scripts/schema.ts` loads `src/editor/schema.ts` through Vite's `runnerImport`, so the registry must stay importable under Node: no DOM at module level.
- **Table controls:** `editor/table.ts`. `TableWithControls` extends TipTap's `TableView` (passed as the table's `View`) with two `+` buttons, `add row` and `add column`, which add at the end and put the caret in the new cell. They sit in `.table-frame`, an inline block as wide as the table inside the scrolling wrapper, so they follow a table wider than the page; `page.css` shows them only on hover and only when the editor is `contenteditable="true"`, so tests hover the table first. `TableMenuOnRightClick` opens a `menu` named `table` on a writer's right click on a cell, in plain DOM with the classes of `Menu.svelte`; a cell selection that holds the clicked cell is kept. Both call `prosemirror-tables` commands with the view's own state, after moving the caret in a transaction of its own. Icon shapes now live in `components/icons.ts`, with `iconMarkup` for menus built without Svelte.
- **Block tests:** `e2e/editing.ts` holds the two-browser fixture and the helpers that `editor.spec.ts` and `blocks.spec.ts` share. A slash opens the menu only at the start of a block or after a space, so a test that types into a cell moves to an empty one first. `:scope > p` finds the paragraph the editor keeps after a final block.
- **Revoked while reconnecting:** a page whose access ends while its socket is reconnecting after a `4409` shows `page not found`, not `access revoked`: the upgrade fails, and REST answers `404` for what one cannot read, as it must. Tests that revoke after a role change wait for `synced … read only` first.
- **Known flaky:** `a source written out in one browser is left alone by a caret passing in the other` (`editor.spec.ts`) fails about one run in four on `main` too, before step 13. Not investigated. In the full run of step 15, it and `two browsers see each other's tree changes` (`navigation.spec.ts`, at its `goto`) failed once, then passed 3 times each; `a source being edited survives the other browser's typing` failed once under four workers too.
- **Attachments:** `attachments.ts` holds the `image` and `file` nodes and imports nothing from Svelte, since `npm run schema` loads the registry in Node, where `$state` does not exist. The uploads (`uploads.ts`) are added by `collab.ts` with the page id, as `PagePicker` is. Uploads go one at a time; after an atom block the selection is that block, so the next one is inserted after it, not over it. A paste test builds its `DataTransfer` in the page (`attachments.spec.ts`), and the slash command answers a `filechooser` event. A file block shows a `file` label, not an icon, since icons stand for verbs, and its size, read with a `HEAD` on the download (axum answers it from the `GET` route) rather than stored in the document.
- **Search (step 18):** `routes/Search.svelte` at `/w/<slug>/search?q=&space=`. The address holds the query, updated with `replace` once typing pauses 200 ms, so a reload or a shared link shows the same results. `Ctrl K` (or `⌘ K`) in `Shell.svelte` goes there, or focuses its field if already there, and the sidebar's search field is a link to it. Excerpts come as `{ text, match }` pieces and render as text with `<mark>`, never `{@html}`. Left for later: the `Ctrl K` command palette of the design system, with results as you type over any screen; the `[[` page picker still filters recent titles in the browser, since search ranks body matches too and the picker wants titles.
