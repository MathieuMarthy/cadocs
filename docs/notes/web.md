# Web

What a change to the front end or its tests must know.

- **Shell:** Svelte 5 with runes (ADR 0004), mounted on `body` by `main.ts`. `App.svelte` holds every route in `resolve`, which also does the redirects: setup while no account exists, login with `?next=` without a session, back to `safeNext(next)` once there is one. So a screen logs in by calling `signIn`, and never navigates for it. `lib/router.svelte.ts` has no dependency: it catches clicks on same-site links, and the server answers `index.html` for any path that is not a file (`assets.rs`, which lists the first segments that are not routes: add `s` with public shares). `lib/api.ts` keeps the CSRF token and sends every `unauthenticated` answer to `sessionEnded`, so a screen need not handle a lost session. Only a `signOut` after a real `POST /auth/logout` or a `refreshSession` that failed may drop the session: the server decides, not the screen. `lib/form.svelte.ts` holds a form's busy state and refusals, and shows a field's code with spaces (`too short`). Screens without a sidebar use `Solo.svelte`, the others `Shell.svelte`. `Source.svelte` has the source link and the theme button, and must stay on every screen (ADR 0010): the shell passes `withTheme={false}`, since its user menu has the theme. `vite.config.ts` builds the link from the commit, or from the tag without Git. The theme is `data-theme` on `<html>`, over `light-dark()` in the tokens, set before the first paint by `public/theme.js`, a file because the CSP refuses inline scripts.
- **Type checks:** `tsc` skips `.svelte` files, and `svelte-check` needs TypeScript 5 or 6 while the project has 7, so it is not a dependency. Run it by hand after changing a component: `npx -y -p typescript@6 -p svelte-check@4.7.8 -p svelte@5.57.3 svelte-check --workspace . --tsconfig ./tsconfig.json` from `web/`.
- **Left for later steps:** step 14 must handle `4409`, which still shows `offline, retrying` and leaves a demoted reader's editor writable, while the server drops what they type. Step 13 adds trashing and restoring a space: the tree only lists live spaces. Moving a page has no keyboard way yet, only drag and drop. The tree menu has no `rename` yet, which the design system lists: `PATCH /pages/{id}` already takes a title. Presence counts awareness clients, so one person in two tabs shows two avatars: step 14 can count by user once awareness carries real users.
- **Navigation:** `lib/nav.svelte.ts` holds a workspace's spaces, tree levels and events socket. `acquireNav` shares one `Nav` between the screens, since each mounts its own `Shell`, and keeps the socket 2 seconds after the last one leaves. A screen that calls it is keyed by workspace in `App.svelte`. A node is open exactly when its level is in `levels`: closing one drops the levels under it, so events only refetch what shows, and templates read `loaded`, never `level`, which would write state while rendering. A page event refetches every loaded level of its space, 50 ms after the first of a burst, and bumps `versions` and `version`, which the trash and recent pages watch. The spaces load over REST at `start`, without waiting for a socket a proxy may never let through. Opening the socket, and `resync`, reload everything, and a space whose role changed reads its levels again, since each row carries the role. Tree drags carry `application/x-cadocs-page`, so a dragged file or text is ignored. `4401` ends the session, `4403` and `4404` refresh it, and anything else retries with backoff, refreshing the session every third failure. A drop on the top quarter of a row goes before it, on the bottom quarter after it, in between under it, and on a space at the end of its root. Logging out now closes the events socket, so the shell goes to login at once.
- **Page view:** `routes/Page.svelte` and `editor/collab.ts`, loaded on demand, so a login does not download TipTap. It sits in the shell (`bare`, with the status and presence in the `end` snippet), placed in its workspace by the `GET /pages/{id}` it reads first. A REST failure that is not `401` or `404` still shows the editor, in a shell with no workspace (`guess={false}`), and the page reads itself again every 2 seconds until it knows where it lives. A change to its space reads it again, so a move updates the breadcrumb, and a read that finds it gone destroys the editor. The tree marks the page the address shows. A screen's `status` role is no longer unique, as the tree has one while loading: tests look for it in `banner` or `main`. Still the prototype page, with `guest-` names, until step 14. `?page=<id>` picks it. It reads `GET /pages/{id}` before opening the socket, and again every 3 failed connections, because a socket cannot read the status of a failed upgrade. Only `401` and `404` stop it. `4401` goes to login, `4403` and `4404` replace the page with a message. `disableBc` is on, so two tabs of one browser really go through the server. Awareness holds `user: { name, slot }`, where `slot` (1 to 3) picks the presence color. The title is a plain input bound to `Y.Text` in `web/src/title.ts`.
- **Shell layout (step 12b):** the sidebar is sticky at the window's height, and only `.sidebar-scroll` (the tree) scrolls; its `scrollTop` lives in a module variable of `Shell.svelte`, since every screen mounts its own shell. Under 840px it is a fixed drawer with `display: none` until `drawer-open`, so a test sees no `complementary` while it is closed. A change of address closes it, Escape closes it unless a menu is open, and a press outside it or its menus closes it. The footer is a `Menu` with `text` (the user's name, not lowercased), whose items are account, `theme: <current>` and log out: tests log out through it (`logOut` in `shell.spec.ts`), but `Invite.svelte` keeps its own `log out` button. The breadcrumb takes `crumbs: { label, href? }[]`, and `crumbWorkspace={false}` on the workspace home, account and admin. `admin` is the only row left under `settings`, so the group shows only to instance admins. Names users typed (workspaces, spaces, pages) keep their case everywhere; only interface words are lowercase.
- **Page view placement:** `GET /pages/{id}` answers `ancestors`, which the breadcrumb links and which the page expands in the tree once per mount (`revealed`), so a user who collapses it later is not overridden by the next re-read. The selected row scrolls into view through an attachment in `TreeLevel`, and again when the drawer opens. While the first read is pending, the page shows a shell on `lastWorkspace` (the tree that showed last) with `loading…` in `main`, so a click in the tree does not flash. Once a read answered or the editor shows without one, only the page's own workspace is used. The re-read on a change to its space only fires for a version it has not seen (`seen`): an effect that runs again for another reason, as after expanding the tree, used to read a revoked page first and show `page not found` instead of `access revoked`. A page opened by its address now has its space open: do not click the space in a test after it, which would close it.
- **Icons and menus:** `components/Icon.svelte` holds the Lucide shapes of the design system's table, as strings drawn with `{@html}` inside one `svg` that carries the stroke settings. Add an icon by copying its shapes from `lucide-static` 0.460.0, never its attributes. `IconButton` takes the verb as `title` and the full label (`new page in Deploy`) as `aria-label`. `Menu` is the `ellipsis` button and its `role="menu"`, a `popover="manual"` in the top layer so a scrolling sidebar does not clip it, placed from the button's box when it opens and closed by a press outside, a scroll or a resize. Its items are `tabindex="-1"` and take focus from the arrows and the pointer. Opened by Enter or Space (a click whose `detail` is 0), it focuses its first item; opened by the pointer, it focuses the menu itself, so no row shows inverted before the pointer reaches it (in the dark theme that row merged with the light border and shadow). A `space-1` padding keeps the active row inside the border. A link item closes the menu without taking focus back. `lib/notice.svelte.ts` holds the one notice, shown by `Notice.svelte`, mounted once in `App.svelte`, and its `status` region exists only while there is a notice, since tests read a screen's single `status`. Mounted there so a screen that changes under it (a trashed page turning into `page deleted`) keeps it. The notice focuses its `undo` and restarts its timer, since that focus is not the reader holding it. An `undo` that restores the page on screen bumps `reopened` (`lib/router.svelte.ts`), part of the page view's key, to mount it again. `Confirm` takes an `icon` and `danger` for a final action in a list row.
- **Tree actions out of layout:** `display: none` until the row is hovered or holds focus, so `getByRole` does not see them: tests point at the row first (`press` in `navigation.spec.ts`) or count with `includeHidden`. An open menu keeps them displayed through `:has([aria-expanded="true"])`, because moving focus from the button to the first item first blurs the button, which would remove the menu with its row and drop focus on `body`.
- **Browser tests:** Playwright reads the browser path from `CHROMIUM_PATH` through `executablePath`, and uses its own Chromium when unset. Any Chromium-based browser works.
- **Slow browser start:** Helium, in a new process, can stall every request for 5 seconds or more, static files too, and then load the page a second time. It does not come from the server, and `requestfinished` shows it. A page opens its socket after three round trips, so this now falls before the socket, and `expect.timeout` is 30 seconds. For a quick loop, `CADOCS_BIN=../target/debug/cadocs` reads `web/dist` at run time and needs no release build.
- **End-to-end tests:** `web/e2e/` runs the real binary, on its own port and temporary data folder (`server.ts`, `CADOCS_BIN` picks another binary). `TestServer` runs first-run setup on the first `session()`, and `page(name)` creates a page per name, so tests keep naming their rooms. Node's `WebSocket` sends the cookie through `webSocketClass()`, passed as `WebSocketPolyfill`, and a browser gets it from `addCookies`. `compat.test.ts` uses `node:test` with the real `yjs` and `y-websocket`, and needs Node 22.18 or later for type stripping and `node:sqlite`. `browsers.spec.ts` uses Playwright, with two real browser processes. `shell.spec.ts` covers the shell, `navigation.spec.ts` the tree, the trash and recent pages, `fixtures.ts` holds what the specs share, and `TestServer` gives them `call`, `invite` and `addMember` for what the test does not go through the interface for. Playwright's `dragTo` drives the native drag and drop of the tree, and `targetPosition` picks the zone. An open client resends its whole document when it reconnects, so a test about the disk must have no client left when the server comes back. A paragraph's text holds the label of a remote caret: read it with `bodyLines`. Do not `goto("about:blank")` before another `goto`: the browser sometimes commits it twice, which aborts the next navigation.
- **Screens (step 12c):** `lib/actions.ts` holds what the tree and the page's top bar share (`copy`, `pageLink`, `trashPage` with its `undo`), so both say `link copied` and `moved to trash`. `NewSpace.svelte` is the space name form, opened by the `plus` beside the `spaces` label (`managesSpaces`: workspace owner or admin) and by the empty home; Escape in its field closes it. `Time.svelte` shows a date as `5 minutes ago`, the exact one in `title`, and refreshes every 30 seconds. The page title is a `textarea` that `editor/title.ts` grows to its text and keeps on one line (a pasted line break becomes a space); tests still read it with `getByLabel("page title")` and `toHaveValue`. Avatars show only from two people, so a test alone on a page sees no `.avatar`. The account has two forms named by their headings (`profile`, `email and password`): tests reach them with `getByRole("form", { name })`. The server asks the current password for a new email too, so the email lives in the second form. Administration actions are in a `more actions for <name>` menu per user; the current admin's menu only has `new reset link`, and `delete` asks again inline with a `danger` button. `Confirm` with `danger` and no `icon` shows both buttons in `danger`. `screens.spec.ts` covers this step, and its theme tests save a screenshot of each screen in `test-results`.
- **Two-class overrides:** `.icon-button` sets `display`, and comes late in `base.css`, so a rule that hides an icon button needs two classes (`.icon-button.drawer-button`). The drawer buttons showed on wide windows until step 12c for this reason.
