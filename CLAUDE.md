# cadocs

Self-hosted collaborative wiki, a lightweight Docmost alternative. Top priority: minimal server RAM (10 to 30 MB idle, under 100 MB for a few dozen active users). One binary plus one data folder, no mandatory external service.

Design lives in `docs/`: read only what the current task needs. `ARCHITECTURE.md` for the flows, `API.md` for the wire protocol, `DATA_MODEL.md` for the schema, `PERMISSIONS.md` for the access matrix, `OPERATIONS.md` for configuration and deployment, `CARGO_WORKSPACE.md` for crates, `ROADMAP.md` for stages and progress, `adr/` for the reasons behind a decision. Do not reopen a decision recorded in an ADR unless a measurement contradicts it. If it does, write a new ADR.

## Commands

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
npm --prefix web ci && npm --prefix web run build   # before a release build: the binary embeds web/dist
cargo build --release
npm --prefix web run test:e2e                       # after the two builds: it runs target/release/cadocs, whose web/dist is embedded
bench/rss.sh build && bench/rss.sh run              # RAM benchmark, about 12 minutes, results in target/bench
```

Run it with `CADOCS_PUBLIC_URL=http://127.0.0.1:3000 target/release/cadocs`. The page needs a session and a page id, and nothing offers them before step 11: `POST /api/v1/auth/setup` from the browser's console, create a space and a page over REST, then open `http://127.0.0.1:3000/?page=<id>`. For front end work, set `CADOCS_PUBLIC_URL` to the Vite address (`http://localhost:5173`), run the server, then `npm --prefix web run dev`, which proxies `/ws` and `/api` to it.

## Workflow

**One session per step.** Work is cut into steps small enough for one session, so state lives in the code and `docs/`, never in a conversation.

Starting a session:
1. Find the first unchecked step of the current stage in `docs/ROADMAP.md`.
2. Read only the docs and code that step needs. Do not re-explore the whole repository.
3. Do that step and nothing beyond it.

Ending a session:
1. Tests and clippy pass, or the failure is reported as is.
2. Get an independent review of the step's code, from a reviewer that did not write it and starts without the session's context (the `code-review` skill or a fresh subagent). Fix what it confirms, with a failing test first, and report what is left open.
3. Check the step in `docs/ROADMAP.md`. Anything learned that changes the design goes into `docs/` or an ADR. Anything later steps must know goes into Notes below.
4. Summarize what was done and what comes next, then stop.

Other rules:
- **Tests first.** Write the failing test, watch it fail, implement, watch it pass.
- **Commit only when asked.** Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`, with an optional crate as scope, as in `feat(collab): add room unloading`.
- **Stay lean on tokens.** Redirect long command output to a file and read its tail. Do not repeat content already shown.
- **Report results as they are.** If a RAM target is missed, say so with the analysis. Never adjust a benchmark scenario to make a number pass.

## Conventions

- **Language:** everything in the repository is in English: docs, code comments, commit messages and UI strings.
- **Errors:** `thiserror` in library crates, `anyhow` in binaries.
- **Dependencies:** each one must justify its RAM and binary cost, and be compatible with AGPL-3.0 (ADR 0010). Update `docs/CARGO_WORKSPACE.md` when adding one.
- **Reference project:** https://github.com/MathieuMarthy/uptime-monitoring uses the same stack (SQLite setup in `src/db.rs`, embedded assets in `src/assets.rs`, release profile).
- **Design:** the UI follows the Brut design system, documented in `docs/DESIGN_SYSTEM.md`, with its tokens in `web/src/tokens.css`. IBM Plex is embedded in the binary, never loaded from Google Fonts (ADR 0004). Brut's examples are in French, and the UI translates them to English.

## Notes

- **Prototype limits:** there is no search or Markdown conversion. The server binds to `127.0.0.1`. Do not expose it.
- **Browser tests:** Playwright reads the browser path from `CHROMIUM_PATH` through `executablePath`, and uses its own Chromium when unset. Any Chromium-based browser works.
- **End-to-end tests:** `web/e2e/` runs the real binary, on its own port and temporary data folder (`server.ts`, `CADOCS_BIN` picks another binary). `TestServer` runs first-run setup on the first `session()`, and `page(name)` creates a page per name, so tests keep naming their rooms. Node's `WebSocket` sends the cookie through `webSocketClass()`, passed as `WebSocketPolyfill`, and a browser gets it from `addCookies`. `compat.test.ts` uses `node:test` with the real `yjs` and `y-websocket`, and needs Node 22.18 or later for type stripping and `node:sqlite`. `browsers.spec.ts` uses Playwright, with two real browser processes. An open client resends its whole document when it reconnects, so a test about the disk must have no client left when the server comes back. A paragraph's text holds the label of a remote caret: read it with `bodyLines`. Do not `goto("about:blank")` before another `goto`: the browser sometimes commits it twice, which aborts the next navigation.
- **yrs 0.28:** `yrs::sync` has `Awareness`, `Message`, `SyncMessage`, `MessageReader`, `DefaultProtocol` and the `Protocol` trait. Filter around `Protocol::handle_message` to reject `SyncStep2` and `Update` in read-only mode. `Doc` is `Send + Sync`. Enable the `sync` feature if the async or observer APIs require it.
- **y-websocket** appends `/<room>` to the server URL. By default it stops for good on close codes 4400 to 4499, so `web/src/main.ts` passes `shouldReconnect`, and any other client of this server must too. The MVP must still show `4401`, `4403` and `4404` in the page: today the status stays at "offline, retrying".
- **Yjs document layout:** root types `title` (`Y.Text`) and `default` (`XmlFragment`, TipTap's default field). See `docs/DATA_MODEL.md`.
- **Store:** `DocStore` (`cadocs-store`) uses native `impl Future + Send` methods, so collab is generic over it instead of using `dyn`. The room assigns `seq`, starting from `StoredDoc::last_seq() + 1`. `compact` refuses a snapshot older than the stored one with `StoreError::StaleSnapshot`. `append_updates` can be replayed after a lost commit, and returns `StoreError::SeqConflict` for a `seq` the snapshot covers or that holds other data. A room must flush its queue before it compacts. `SqliteStore::open` takes the database file path, and its parent folder must exist. There is no in-memory store or `close()` yet. `StoreError` wraps `sqlx::Error`, so a failure-injecting test store can return `sqlx::Error::PoolTimedOut`. A document needs its row in `pages`, so a test on `SqliteStore` inserts one, and `append_updates` and `compact` answer `PageNotFound` without it. `append_updates` also takes a `DocEdit`, the title and author for that row, whatever the batch.
- **Permissions:** `cadocs-core::permissions` covers the matrix, the special cases and the recompute of page sockets. The recompute of events sockets comes in step 9. `would_remove_last_instance_admin` is a separate check, called by `delete_user` and `administer_user` in the store. `Authorizer` and `PageAuthorizer`, which resolves the role through `PageStore` and the session through `AccountStore`, are in `cadocs-collab`. **A handler whose change can alter what a user reaches calls `state.access_changed()` once it is stored**: that wakes `watch_access` in `lib.rs`, which runs `DocRegistry::recheck` over every socket, and step 9 hooks events sockets there. It does not wait, so a test waits for the close frame. The timer of `CADOCS_SOCKET_RECHECK_SECS` covers expired sessions, commands beside the server and a failed pass. `upgrade` rechecks once after joining, which closes the race with a change landing before the join. A pass costs two queries per socket with no dedupe, and step 23 should measure it at `CADOCS_MAX_SOCKETS`. A socket never extends its session, and it cannot: the browser's cookie only renews on a REST response. So step 11 must call `GET /session` from time to time while a page is open, or an editor making no REST call gets `4401` at the end of the lifetime. Tests about something else use `Fixed` in `tests/server.rs`.
- **Collab:** `DocRegistry::connect(doc, mode, user, session)` returns a `Connection`, and the server only moves bytes: `receive(frame)` (an `Err(Close(code))` means close with it) and `next().await` (cancel safe, `Frame` or `Close`). `DocRegistry::set_title` is the only write from the server. Another one goes through `enter`, which runs under the registry lock, and through `Room::enqueue`, so it is stored and broadcast like an edit. Hide `yrs` behind such methods: `cadocs-server` has it as a dev dependency only. A flush that gets `PageNotFound` calls `Room::abandon`, which closes the sockets with `4404`: a recheck closes them earlier, this stays as the last resort. The room keeps one author per queue, the last one, so a batch of two users credits one. `set_title` refuses a title root that holds more than text, which only a crafted client can write: `PATCH` then answers `500` for that page, and nothing resets it yet. `PATCH` checks the role again once the room is live, because a write to a room cannot sit in a database transaction: only a demotion or a trash in the few instructions left can still let the edit land, and `append_updates` ignores `deleted_at`.
- **Page socket:** `/ws/pages/{page}` sits behind `api::check_origin` and `session::require` as route layers, in that order, and the handler reads `Extension<CurrentSession>`. So the refusals are the JSON ones of REST, and the upgrade touches the session. `tests/page_socket.rs` has real roles over real sockets.
- **Server:** `cadocs-server` is a library plus the `cadocs` binary. `serve::<S, A, E>` takes the store, the authorizer and the embedded assets as type parameters, so tests pass a failing store and fixture assets. One task per socket does everything (`ws.rs`), because `Connection::next` takes `&mut self`: a blocked send stops that socket's reads, up to `CADOCS_PING_TIMEOUT_SECS`. The `tungstenite` version must stay the one axum uses, or the downcast behind `1009` stops matching (a test covers it). `serve` flushes rooms before it waits on HTTP, and bounds that wait, because a stalled client would otherwise hold up shutdown. A frame far over the limit can lose its `1009` to a TCP reset: `recv` ends at the capacity error, so the rest is never read.
- **HTTP foundation:** `api.rs` holds `ApiError` (build from `ErrorCode`, return it with `?`) and `api::router`: add REST routes before its `finish` call, which only reaches the routes that already exist. `api::rate_limit` is a route layer over `(Arc<RateLimiter>, Arc<HttpConfig>)`, and `api::count_request` does the same from a handler. Test a limit over a real socket, as `tests/auth.rs` does, since only `serve` provides the real `ConnectInfo`. The burst and refill of each limiter are chosen where it is wired. `RateLimiter` counts an IPv6 /48 as one client and tracks 4096 clients at most. Past that a newcomer waits, so 4096 live addresses or sites can hold up strangers, but never reset a client. `security::add_headers` covers every response and leaves alone what a handler set. `PublicUrl::allows` accepts a missing `Origin`, so REST must not rely on it alone. `/api/v1/` needs its own line in `router`, because a nest cannot reach it, so it answers `404` to any `Origin`.
- **Accounts and sessions:** add a route that needs a user to `authenticated` in `api/auth.rs`, or put `session::require` on it: that layer checks the session and CSRF, and handlers read `Extension<CurrentSession>`. `AccountStore` (`cadocs-store`) sits beside `DocStore`, and the server needs both. Read bodies with `api::JsonBody`, whose refusals are in the error shape. A storage error becomes `503` through `From<StoreError>`. Whatever depends on a password check must hold when the write happens, because a hash can wait 10 seconds: `create_session`, `UpdateBasis` and `use_password_reset` re-check inside the write. Nothing tells a client that first-run setup is pending, as `GET /session` answers `401` either way: step 11 needs a public read of `has_users`. A failed session touch retries on each request, each waiting up to 1 second, and has no back-off.
- **Instance administration:** `api/admin.rs` holds `/admin/users`, behind `session::require` and a role check. `api::PageQuery` and `api::Page` are the pagination of every list, and `api::PathParam` reads a path parameter with its refusal in the error shape. `axum` has no `query` feature, on purpose. A reset link is `<public url>/reset-password/<token>`, and step 11 must serve that page, which posts to `/auth/password-reset/{token}`. `assets::serve` answers `404` for it today. `SqliteStore::open_existing` is for commands beside a live server: it neither creates nor migrates. The links an admin made go when they are disabled, demoted or deleted. An admin who deletes or disables themself through `/admin/users` gets no removal cookie, unlike `DELETE /me`: the next request is a `401`, which step 11 must handle. `tests/common` holds the REST test client.
- **Workspaces:** `WorkspaceStore` (`cadocs-store`) sits beside the other two stores. A method takes the actor and checks the role itself, through `authorize` in `sqlite/workspaces.rs`, inside the transaction for a write, so a route cannot forget it, and step 5 should do the same. The last owner check counts the enabled owners who would stay, as `delete_user` does. `PathParam<(String, String)>` reads two path parameters. `Page`'s rows come from `PageQuery::fetch` and `cut`. An invitation link is `<public url>/invite/<token>`, and step 11 must serve that page, which needs a login when `has_account` is true. `session::require_in_handler` is `require` for a route open to everyone. Changing `language` must queue a reindex in step 18. Expired invitations stay until the purge of step 10. `GET /invitations/{token}` has no rate limit: a token cannot be guessed, so this only costs load, a hash and a read per request. Step 24 should weigh it.
- **Spaces:** `SpaceStore` (`cadocs-store`) sits beside the other stores. `authorize` in `sqlite/spaces.rs` resolves the role through `SELECT_SPACE` and `cadocs-core`, and turns a refusal into `SpaceNotFound` or `NotAllowed`: step 6 should use it, and pass `page_trashed` through a `Scope` of its own. `group_members` and group grants are read by resolution, and `PUT /grants` writes group grants, but nothing makes groups before V1, so tests insert them with SQL. A trashed space stays until the purge of step 10. `GET /workspaces/{ws}/spaces/trash` was added so that a restore has something to start from.
- **Pages:** `PageStore` (`cadocs-store`) sits beside the other stores, and `authorize` in `sqlite/pages.rs` resolves through `SELECT_PAGE`. `POST /spaces/{space}/pages` takes no title: the Yjs document holds it. `page_to_edit` is the check of a change that goes through a room. Nothing here publishes an event: step 9 hooks into `move_page`, `trash_page`, `restore_page` and `purge_page`. The server computes `position` from `after`, and a key only ever grows: a script alternating moves after one sibling inflates it, and it is also the tree cursor, so step 24 should weigh a cap. `tree` resolves the role per row, and deleting a user scans `pages` for its three `SET NULL` columns: step 23 should measure both. A tree has at most `MAX_PAGE_DEPTH` levels because of SQLite's limit on nested triggers.
- **Socket RAM:** tungstenite's write buffer keeps the capacity of the largest frame sent, and no option shrinks it, so each socket holds about one SyncStep2 of its document for its whole life. Measured at 62 KiB per socket on the 20 KB benchmark document.
- **Front end:** plain TypeScript and TipTap for now, Svelte comes with the MVP shell (ADR 0004). `?page=<id>` picks the page, and without it the page only says so. `disableBc` is on, so two tabs of one browser really go through the server. Awareness holds `user: { name, slot }`, where `slot` (1 to 3) picks the presence color. The title is a plain input bound to `Y.Text` in `web/src/title.ts`.
- **yrs hardening:** yrs 0.28 can panic and even segfault on crafted updates, in release too, and `catch_unwind` only covers panics. Write access means trust, and this risk is accepted (ADR 0014). Keep unwinding on. `mutated_frames_do_not_break_the_room` pins client ids so it does not crash at random. A dependency that never arrives blocks compaction until the log reaches 4 times `compact_updates`, and a stored row that cannot be applied (`skipped_row`) still blocks it for good. Awareness ownership is by user, because a reconnecting client reuses its id, so two tabs of one user can overwrite each other. `user` in a state is not validated, only `cursor` is.
- **Store load:** `load` holds a document's whole update log in memory. Measured at 3.0 MB more for 100 documents of 2,000 rows, so it stays.
- **Benchmark:** the scenario and go or no-go rule in `docs/ARCHITECTURE.md` are fixed. Do not change them to make a number pass. Stage 0 ended on a go, after ADR 0015 added `malloc_trim` on unload. A loaded document costs about 530 KiB, 10 to 15 times its encoded size, so 256 rooms would pass 100 MB: the MVP must keep that in mind when it sets `CADOCS_MAX_ROOMS`. `cadocs-bench seed` also makes the account behind `SESSION_TOKEN`, and needs an empty database. `cadocs-bench` is outside `default-members`: `--workspace` covers it, and building it with the server changes the server's features. glibc's in-use bytes need a preload probe, because `ptrace_scope` blocks `gdb -p`.
